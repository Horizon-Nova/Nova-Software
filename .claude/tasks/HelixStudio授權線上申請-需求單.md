# HelixStudio 授權申請 需求單（HelixStudio 端的做法）

2026-09-24

HelixStudio 的授權是：客戶在離線電腦上產生「申請碼」，賣方把申請碼變成一把簽過章的「KEY」，客戶再把 KEY 貼回同一台電腦。本文件寫的是 HelixStudio 這一端：申請碼和 KEY 的確切格式、簽章方法、HelixStudio 怎麼驗 KEY。線上申請的系統照這份產出 KEY 即可，系統本身怎麼做不在本文件範圍內。

## 1. 原話（需求出處）

1. 「我是綁一台電腦的如果他要在另一台那他就要再跟我們買」
2. 「你可以用簽章但要注意不要依賴線上因為工廠和大部分客戶都不會開放線上功能」
3. 「到期了就擋」
4. 「我們是一機一軟體一工具 他沒辦法分享給其他人」

由 2 推出：HelixStudio 那台電腦不連線。線上申請是客戶用另一台能上網的裝置去送，HelixStudio 只負責產生申請碼、接收 KEY。

## 2. 申請步驟

**首次啟用**

1. 客戶在要使用的電腦上安裝 HelixStudio，打開。
2. 這台電腦還沒有授權，畫面直接出現「啟用這台電腦」。
3. 客戶按右上角「複製申請碼」。申請碼裡是這台電腦量到的機器識別，不含個人資料。
4. 客戶把申請碼交給賣方：用另一台能上網的裝置，貼到線上申請。那台 HelixStudio 的電腦本身不用上網。
5. 賣方收到申請碼，決定三件事：客戶名稱、准裝哪幾支工具、到期日（可以不設，就是永久）。
6. 賣方用發證私鑰，把申請碼和這三件事簽成一把 KEY（格式和簽法見第 4、5 節）。
7. 賣方把 KEY 交給客戶。
8. 客戶把 KEY 貼到 HelixStudio 的「貼上授權」，按「套用授權」。
9. HelixStudio 驗過（第 6 節）就直接進平台；之後每次開啟都直接進平台，不會再出現這個畫面。
10. 驗不過，欄位下方會顯示「授權碼驗證失敗，請確認完整貼上，或向供應商重新索取一次。」，客戶回到第 4 步跟賣方確認。

**加購工具、到期續約**

1. 同一台電腦沒換的話，賣方用那台上次的申請碼重發一把 KEY：加購就是准裝清單多加那支工具，續約就是換新的到期日。
2. 加購的話，賣方另外把那支工具的套件檔（`.stpkg`）交給客戶。
3. 客戶在 HelixStudio 設定 → 授權 →「停用這台裝置的授權」，回到「啟用這台電腦」，貼上新 KEY（這個入口還沒做，見第 7 節）。
4. 加購的話，客戶再到工具目錄「匯入工具套件…」選那個檔案。

**換電腦**

1. 客戶在新電腦上照「首次啟用」重來一次，申請碼是新電腦的。
2. 舊電腦上的 KEY 沒辦法遠端作廢，只能等它自己到期；要不要另外處理，由賣方決定。

| 情境 | 申請碼 | KEY |
|---|---|---|
| 首次啟用 | 客戶新產生 | 新發 |
| 加購工具 | 同一台電腦可以沿用上次的申請碼 | 新發，准裝清單多加那支工具 |
| 換機 | 新電腦新產生 | 新發，綁新電腦；舊 KEY 沒辦法遠端作廢，只能等它到期 |
| 到期續約 | 同一台電腦可以沿用 | 新發，換新的到期日 |

## 3. 申請碼格式

申請碼 = base64( UTF-8( JSON ) )，JSON 只有一個欄位：

```json
{"Marks":[{"Kind":"主機板序號","Value":"07D4650_OA1E703798"},{"Kind":"處理器","Value":"BFEBFBFF000B0671"}]}
```

- `Marks`：這台電腦**量得到的每一項**機器識別。讀不到的那一項就不出現，所以每台電腦的項數不一定相同。
- 同一種可以有好幾筆，例如好幾張網卡、好幾顆硬碟，各佔一筆。
- 屬性名大小寫要完全一樣（`Marks`、`Kind`、`Value`）。
- 中文會被寫成 `\uXXXX` 跳脫字元，解 JSON 時要照標準還原。
- 長度大約 850 字元，實際長度看量到幾項。

目前 HelixStudio 量的 `Kind`（來源：`HelixStudio\Store\DeviceStore.cs`）：

| Kind | 從哪裡讀 |
|---|---|
| 主機板序號 | WMI `Win32_BaseBoard.SerialNumber` |
| 處理器 | WMI `Win32_Processor.ProcessorId` |
| BIOS 序號 | WMI `Win32_BIOS.SerialNumber` |
| 機器 UUID | WMI `Win32_ComputerSystemProduct.UUID` |
| 硬碟序號 | WMI `Win32_DiskDrive.SerialNumber`（每顆一筆） |
| 網卡 | WMI `Win32_NetworkAdapter`（實體網卡）`MACAddress`（每張一筆） |
| Windows 安裝 | 登錄檔 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` |

線上系統不必看懂這些值，只要**原封不動**抄進 KEY 的 `Marks` 就好。

## 4. KEY 格式

KEY = base64( UTF-8( JSON ) )：

```json
{
  "Customer": "曜域科技 Vaeron",
  "Issued": "2026-09-24",
  "Expires": "2027-12-31",
  "Tools": ["local.checksum"],
  "Marks": [ …從申請碼原樣抄過來… ],
  "Signature": "base64…"
}
```

| 欄位 | 規則 |
|---|---|
| `Customer` | 客戶名稱，任意文字，可以是空字串 |
| `Issued` | 發證日，`yyyy-MM-dd` |
| `Expires` | 到期日，`yyyy-MM-dd`；空字串＝永久。格式看不懂的，HelixStudio 一律當成已經過期 |
| `Tools` | 准裝的工具代碼陣列，代碼＝工具套件 `manifest.json` 的 `tool_no`（例：`local.checksum`）；空陣列＝全部工具（這條規則待決定，見第 8 節） |
| `Marks` | 從申請碼原樣抄過來，一筆都不能改、不能少 |
| `Signature` | 簽章，見第 5 節 |

- 屬性名大小寫要完全一樣，HelixStudio 讀 JSON 時分大小寫。
- 客戶貼上的 KEY 前後有空白會自動去掉。

## 5. 簽章

- **演算法**：RSA 2048 位元，SHA-256，PKCS#1 v1.5 填充。
- **被簽的內容**：下面這段「正規化文字」的 UTF-8 位元組，先算 SHA-256，再用私鑰簽。
- **`Signature`**：簽出來的位元組轉成 base64。

正規化文字（每一行用 `\n` 接起來，最後一行後面沒有換行）：

```text
<Customer>
<Issued>
<Expires>
<Tools 依序數排序後用逗號接起來>
<每一筆 Marks 寫成 Kind=Value，先依 Kind、再依 Value 序數排序，一筆一行>
```

- 「序數排序」＝比字元碼，不依語系規則（等同 C# 的 `StringComparer.Ordinal`）。
- `Expires` 空的那一行就是空行；`Tools` 空的那一行也是空行。

例（`Tools` 兩支、`Marks` 兩筆）：

```text
曜域科技 Vaeron
2026-09-24
2027-12-31
local.checksum,qr.gen
主機板序號=07D4650_OA1E703798
處理器=BFEBFBFF000B0671
```

**金鑰**
- **發證私鑰**：PKCS#8 PEM，現在在 `Nova-Software\Vaeron-Software\Vaeron.Software\keys\helix-licence-key.pem`，不進版控、不進備份。
- **對應的公鑰**：已經拆段加遮罩，寫死在 HelixStudio 裡（`HelixStudio\Core\Anchors.cs` 的 `Licence()`）。
- 線上系統**必須用這一把私鑰**簽，HelixStudio 才驗得過。換一組金鑰，HelixStudio 就要換公鑰、重新發佈，而舊 KEY 全部會失效。
- 私鑰放在哪裡、由誰按下簽章，是線上系統那邊要決定的（見第 8 節）。私鑰一旦外流，任何人都能簽出 HelixStudio 會接受的 KEY。

**參考實作**：`HelixStudio.Pack\Licencer.cs` 的 `Issue` 與 `Canonical`。命令列 `helixkey issue` 做的就是本節全部；線上系統產出的 KEY，可以拿它發的來對照。

## 6. HelixStudio 怎麼驗 KEY

KEY 存在 `%LOCALAPPDATA%\HelixStudio\licence.key`。以下四個條件同時成立才放行：

1. **簽章**：用內建公鑰驗第 5 節的簽章，通過。
2. **機器**：KEY 裡的 `Marks` 和這台電腦現在量到的，只比兩邊都有的 `Kind`。
   - 每一種都至少要有一個值相同。
   - 某一種這台讀不到的，不算不符。
   - 兩邊完全沒有同一種 `Kind` 的，算不符。
3. **到期**：`Expires` 空，或今天 ≤ `Expires`（到期日當天仍可用）。
4. **工具**：只在匯入工具和開啟工具時檢查。工具代碼要在 `Tools` 裡，`Tools` 空的算全部。

| 檢查點 | 檢查哪幾項 | 不通過時 |
|---|---|---|
| 開啟 HelixStudio | 1、2、3 | 顯示「啟用這台電腦」，要貼新 KEY |
| 按「套用授權」 | 1、2、3 | 顯示「授權碼驗證失敗，請確認完整貼上，或向供應商重新索取一次。」 |
| 匯入工具 | 1、2、3、4 | 通知「這台電腦的授權沒有包含 ○○○。跟供應商加購這一支，換一把新的授權。」 |
| 開啟工具 | 1、2、3、4 | 同上，停在工具資訊頁 |

四個檢查點各自重新驗一次，不共用之前的結果。

## 7. HelixStudio 端還要補的

| 項目 | 說明 |
|---|---|
| 已有授權時換 KEY 的入口 | 現在只有沒授權時才看得到「貼上授權」，加購、續約的客戶沒有地方貼新 KEY。照設計圖 `DesktopShell.dc.html`（約第 2620 行）的設定頁「授權」區塊：顯示客戶、到期日、准裝工具，加上「停用這台裝置的授權」，按下去回到「啟用這台電腦」 |

## 8. 待決定事項

| # | 事項 | 影響 |
|---|---|---|
| 1 | `Tools` 空陣列的意義：「全部工具」或「一支都不准」 | 原話 4「一機一軟體一工具」傾向後者；改了之後，HelixStudio 第 6 節第 4 項要跟著改 |
| 2 | 發證私鑰放在線上系統的伺服器，還是由內部人員離線簽好再貼回系統 | 決定私鑰外流的風險 |
| 3 | 一把 KEY 預設發多久 | 原話 3 只規定到期要擋 |

## 9. 驗收

| 功能 | 驗證方式 | 通過標準 |
|---|---|---|
| 格式相容 | 同一個申請碼，分別用線上系統和 `helixkey issue` 發 KEY，客戶、日期、准裝清單都填一樣 | 兩把 KEY 解開後，除了 `Signature` 以外每個欄位都相同，而且兩把都能讓 HelixStudio 進平台 |
| 正規化文字 | 拿線上系統算出的正規化文字，跟 `Licencer.Canonical` 的結果比 | 逐字元相同 |
| 機器綁定 | 把 KEY 貼到另一台電腦 | 被擋 |
| 竄改 | 改 KEY 裡任何一個欄位再貼 | 被擋 |
| 到期 | 發一把到期日是昨天的 KEY | 被擋；到期日是今天的可以用 |
| 准裝清單 | KEY 只准 A 工具，去匯入 B 工具 | 匯入被擋；開 B 工具也被擋 |
| 換 KEY | 已有授權時，到設定 → 停用授權 → 貼新 KEY | 回到平台，設定頁顯示新的到期日與准裝工具 |
