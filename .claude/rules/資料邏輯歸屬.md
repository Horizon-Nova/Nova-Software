# 資料邏輯歸屬

## 規則

資料邏輯一律由資料庫承載。專案端只做兩件事：取出資料庫已經投影好的列，交給顯示層。

專案端不得出現判斷式。看到判斷式，代表某段資料邏輯還留在專案端，回頭把它移進資料庫。

## 判定：什麼是資料邏輯

問一句——**這件事的答案會不會隨資料而變？**

會，就是資料邏輯，歸資料庫。

| 屬於資料邏輯 | 承載位置 |
|---|---|
| 值域對映（狀態代碼 → 顯示字樣、圖示名、事件等級、排序次序） | 對照表 |
| 門檻分級（佔用量 → 熱度等級） | 門檻表，取最後一個不大於當前值者 |
| 過濾（只顯示某些狀態、關鍵字搜尋） | view 的 WHERE |
| 排序（可排序欄位、預設方向、取值方式） | view 的 ORDER BY 與欄位定義表 |
| 聚合（合計、計數、摘要文字） | view |
| 有無值（NULL 即 N/A） | 欄位本身為 NULL，不由字串長度反推 |
| 可否編輯、必填、可設範圍 | 欄位定義表 |

不屬於資料邏輯的，留在專案端：

| 不屬於 | 承載位置 |
|---|---|
| 版面尺寸（欄寬、圓角、字級、間距） | `Themes/Tokens.xaml` |
| 顏色本身 | `Themes/Colors.xaml` |
| 等級字串 → 用哪個筆刷 | XAML `Style` 的 `DataTrigger`，key 是資料庫給的等級字串 |
| 視窗行為（最大化、拖曳、面板收合） | 顯示層 |

## 邊界

資料庫給的是**值**，不是外觀。

資料庫回「這一列的熱度等級是 `hot`」，不回「這一列是紅色 `#AC3225`」——換主題時資料庫不必動。顯示層以 `hot` 為 key 查出筆刷，那是查表（§2.3），不是判斷式。

## NULL

欄位沒有設定值時，資料庫存 `NULL`。

專案端不得以空字串、長度為零、鍵不存在等方式代替 NULL，也不得由這些反推「有沒有值」。顯示層拿到 NULL 就顯示 `N/A`，這是 NULL 這個值的呈現，不是判斷。

## 結構來源

結構的來源在資料庫端（vaeron-skeleton 分析器 VAE023）。桌面軟體以打包的 `.sql` 結構定義檔自建資料庫；型別由映射工具自資料庫產生，不由 C# 反推。

對照表與門檻表同樣是表，跟著 `.sql` 一起打包。新增一種狀態、一個等級、一欄排序欄位，都是插一列資料，專案端不動。

## 分層

| 層 | 內容 |
|---|---|
| 共用層 `Shared/` | `DbContext`、主表映射型別（VAE021／VAE022） |
| 功能組件 | view 映射型別（keyless）與查詢；不含 `DbContext`、不含主表、不含對照表 |
| 顯示層 | 版面與外觀；以資料庫給的值為 key 查外觀 |
