# 工程藍圖：Helix-Studio 行程控制

## 定性

| 問題 | 回答 |
|---|---|
| 本質是什麼 | 「停用」是對 Windows 下達結束行程，「啟動」是執行安裝路徑上的執行檔。兩者都是對機器動手，不是改資料庫欄位。狀態不由按鈕決定，由下一輪探索觀測而得。 |
| 完整生命週期是什麼 | 使用者按下 → 依該列目前的狀態與是否為系統關鍵行程查出要做的動作 → 對該軟體的全部行程執行 → 寫事件日誌 → 下一輪探索觀測到行程消失／出現 → 狀態自行變動。 |
| 現有最小結構能否表達 | 不能：目前按鈕只寫 `software.state`，兩秒後被探索覆寫，等同無效果。狀態既然是觀測值，就不該有寫入路徑，`state_presentation.next_state` 一併刪除。 |

## 主體順序

本藍圖採用**結構順序**（由下而上：事實 → 動作對照 → 執行 → 觀測回饋），與既有藍圖同一種，全篇僅此一種。

## 骨架

| 順序 | 項目 | 內容 |
|---|---|---|
| 1 | `software.is_critical` | Windows 的 `IsProcessCritical` 給的事實，與 `has_window`、`session_id` 同一批取得。結束系統關鍵行程會使 Windows 立即停止，故此事實必須存在。判斷依據是這個事實，不是行程名單。 |
| 2 | `toggle_action` | key 為（狀態、是否關鍵）。每一種組合一列，內含按鈕字樣、提示、圖示、可否按、以及要執行的動作名稱。新增一種狀態或一種限制＝多一列。 |
| 3 | 動作 | 動作名稱的值域是 `terminate`／`launch`。專案端以此為 key 查出要跑的東西，不認得「停用」「啟動」這兩個中文詞。 |
| 4 | 結束 | `OpenProcess(PROCESS_TERMINATE)` + `TerminateProcess`，以回傳值表達成敗。不用 `Process.Kill`：拒絕存取時它擲例外。 |
| 5 | 啟動 | `ShellExecuteEx` 執行 `software.exe_path`，以回傳值表達成敗。 |
| 6 | 狀態 | 沒有任何寫 `software.state` 的路徑。行程結束後下一輪探索的集合差運算把它標為 `stopped`。 |

## 技術規範遵循

| 規範 | 是否符合 | 說明 |
|---|---|---|
| 資料邏輯歸屬 | 符合 | 按鈕字樣、可否按、要跑哪個動作，全部在 `toggle_action`。專案端只執行動作名稱對應的那一件事。 |
| 值域不得被塌縮 | 符合 | `is_critical` 是 Windows 給的事實而非本端算出的布林，`toggle_action` 的複合 key 與既有 `edit_state` 同形。不可按的組合在查詢時就不回傳動作，故專案端沒有「什麼都不做」的那一條路。 |
| NULL 即 N/A | 符合 | `exe_path` 為 NULL 的軟體查不到 `launch` 動作。 |
| 是否偏離設計稿 | 無 | 設計稿的提示字即「停用（不論是否當掉，強制結束）」。 |

## 驗收

| 項目 | 分析（我推導） | 驗證（外部系統實際跑過） |
|---|---|---|
| 每行程網路無計數器可用 | — | 已驗證：`Get-Counter -ListSet Process` 的計數器只有 Virtual／PageFile／Private／Pool／IO 各項 Bytes，無網路項 |
| 機器整體網路有計數器可用 | — | 已驗證：`Network Interface` 一個 instance（MediaTek MT7921 Wi-Fi 6），`Bytes Total/sec` 原始值 9127995485 |
| ETW 需提權 | — | 已驗證：目前執行身分 `elevated: False`，故 per-process 網路維持 N/A |
| 按下停用後行程真的消失 | — | 已驗證：Notepad（pid 23636）按下後 `Get-Process Notepad` 回 False，該列轉「已停止」、讀數變「—」、按鈕變「啟動」 |
| 按下啟動後行程真的出現 | — | 已驗證：同一列按下後 `Get-Process Notepad` 回 True，pid 25396 |
| 機器整體網路 | — | 已驗證：畫面顯示 1.4 Mbps／1.9 Mbps 隨流量變動 |
| 系統關鍵行程的按鈕不可按 | `IsProcessCritical` 供給 `is_critical` | 未成立：非提權身分下 `OpenProcess` 對受保護行程失敗，取不到關鍵性，`is_critical` 一律為 0，按鈕仍可按 |

未驗證清單（依賴外部系統精確行為、無法執行驗證的項目，逐條列出，是交付物的一部分）：
- 非提權身分下對其他使用者或受保護行程（防毒）呼叫 `TerminateProcess` 會被拒絕，該次按下沒有效果且不會有錯誤提示。此路徑未實測。
- `IsProcessCritical` 需要 Windows 8.1 以上；更舊的版本上此呼叫不存在。
- ETW 每行程網路取值未實作，提權後的行為未驗證。
