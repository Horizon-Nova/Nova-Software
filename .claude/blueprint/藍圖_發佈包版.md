# 工程藍圖：Helix-Studio 發佈包版

## 定性

| 問題 | 回答 |
|---|---|
| 本質是什麼 | 一組建置產出物：帶有產品中繼資料與 Logo 的執行檔，以及三種散佈形式（`.msi` 安裝檔、`.exe` 安裝程式、免安裝 `.zip`）。哪些形式要產出，由建置組態決定——組態名稱是 key，對應一份產出清單。 |
| 完整生命週期是什麼 | `build.ps1` 建置方案 → 呼叫 `Build/Package.proj` → `Package.proj` 依 `$(Configuration)` 匯入該組態的產出清單 → 逐項執行（`dotnet publish` → WiX 打包 → 壓縮）→ 產出物落在 `artifacts/`。Debug 組態的清單為空，逐項執行跑零次。 |
| 現有最小結構能否表達 | 不能：新增最小結構，理由：`Net/Helix-Studio/` 目前沒有任何產出物定義，`build.ps1` 只呼叫 `dotnet build`。中繼資料則沿用既有 `Directory.Build.props`，不新增檔案。 |

## 主體順序

本藍圖採用**結構順序**（由下而上：資產 → 中繼資料 → 產出清單 → 打包定義 → 觸發點），與既有兩份藍圖同一種，全篇僅此一種。

## 骨架

| 順序 | 項目 | 內容 |
|---|---|---|
| 1 | `Assets/` | 自 `D:\Workplace\Vaeron_Assets\images` 複製 `Vaeron_icon.ico` 進 repo。建置不得依賴該絕對路徑——別台電腦沒有它。 |
| 2 | `Directory.Build.props` 中繼資料 | `Company=Vaeron`、`Product=Helix Studio`、`Copyright=Copyright © $([System.DateTime]::Now.Year) Vaeron`、`Version`／`AssemblyVersion`／`FileVersion` 取自 `VersionPrefix`。比照 vaeron-skeleton `Directory.Build.props` 第 20-23 行的慣例，補上該處沒有的 `Product` 與 `Copyright`。 |
| 3 | `ApplicationIcon` 與視窗圖示 | App 專案設 `<ApplicationIcon>`，`MainWindow` 設 `Icon`。前者決定檔案總管與工作列圖示，後者決定視窗本身；本專案是自繪標題列，標題列不顯示圖示，`Icon` 的作用在工作列與 Alt+Tab。 |
| 4 | `Build/Package.<組態>.props` | 每個建置組態一份，內容是該組態要產出的形式清單（`PackageArtifact` 項目）。`Release` 列三項：`Msi`／`Bundle`／`Portable`；`Debug` 列零項。檔名由 `$(Configuration)` 組出，無條件匯入——新增組態即新增一份檔案，不動任何既有檔案。 |
| 5 | `Build/Installer/Package.wxs` | WiX 5 的 `.msi` 定義：安裝目錄、檔案清單、開始功能表捷徑、新增移除程式的圖示與版權欄位、`MajorUpgrade`。 |
| 6 | `Build/Installer/Bundle.wxs` | WiX 5 Burn 的 `.exe` 定義：包住上一項的 `.msi`，產出單一檔案安裝程式。 |
| 7 | `Build/Package.proj` | 逐項處理 `PackageArtifact` 清單。`build.ps1` 於建置後無條件呼叫它。 |

## 技術規範遵循

| 規範 | 是否符合 | 說明 |
|---|---|---|
| 禁止 Interface | 不適用 | 本次交付沒有 C# 程式碼。 |
| DI 統一用 primary constructor | 不適用 | 同上。 |
| 是否偏離 template/ 規範（＝污染） | 部分偏離，逐項列出理由 | (1) vaeron-skeleton 沒有任何打包定義，本藍圖新增的部分無既有慣例可循，以 MSBuild 原生機制表達。(2) 骨架 `Directory.Build.props` 的 `Company` 取自 `WorkspacePrefix`，本專案沒有 `Workspace.props`，直接寫 `Vaeron`。 |
| 組態差異不以分支表達 | 符合 | 「哪個組態產出什麼」以 `Package.<組態>.props` 的檔名為 key 查表（§2.3）：組態名是 MSBuild 平台定義的值域，新增一個組態只多一個檔案，`Package.proj` 的結構不動。清單為空時逐項處理跑零次，不是被跳過的分支。 |

## 驗收

| 項目 | 分析（我推導） | 驗證（外部系統實際跑過） |
|---|---|---|
| WiX 5.0.2 可用 `dotnet build` 產出 msi | — | 已驗證：探針專案建置成功產出 `Probe.msi`。WiX 7.0.0 同一份探針以 `WIX7015` 擋下，要求接受 OSMF EULA |
| exe 檔案屬性含公司、產品、版權、版本 | MSBuild 中繼資料寫入組件資訊 | 應用程式 exe：Company `Vaeron`／Product `Helix Studio`／Copyright `Copyright © 2026 Vaeron`／FileVersion `0.1.0`。安裝程式 exe 同上 |
| msi 產品屬性正確 | — | 以 WindowsInstaller 讀出：ProductName `Helix Studio`、Manufacturer `Vaeron`、ProductVersion `0.1.0`、ARPPRODUCTICON `AppIcon`、UpgradeCode `{B91554BB-88A6-4BE4-8809-15F8FBFB5469}` |
| exe 與工作列顯示 Vaeron 圖示 | `ApplicationIcon` 與 `Window.Icon` | 自兩個 exe 取出圖示皆為 Vaeron 標誌；工作列截圖確認使用中視窗的圖示相符 |
| Release 產出 msi／exe／zip 三項 | 產出清單三列 | `HelixStudio.msi` 49.8 MB（cab 已內嵌）、`HelixStudio-Setup.exe` 50.4 MB、`HelixStudio-Portable.zip` 59.4 MB |
| Debug 不產出任何安裝檔 | 產出清單零列 | `build.ps1 -Configuration Debug` 後 `artifacts` 目錄不存在 |

## 踩過的坑

| 現象 | 成因 |
|---|---|
| `WIX0200` 找不到擴充功能 | `Restore` 與 `Build` 在同一次 MSBuild 評估內執行時，擴充套件註冊自己的 `build\*.props` 在評估當下還不存在。改以 `dotnet build` 分屬兩次評估 |
| 同上，另一成因 | 中央套件版本管理會讓 WiX 擴充套件的 build 目錄注入不到編譯器。`Build/Directory.Packages.props` 對打包專案關閉它 |
| `WIX0311` 代碼頁 | 引入 WixUI 後套件語系綁到 1252，中文字串無法編碼。`Package/@Codepage="65001"` |
| 傳給子建置的路徑吃掉下一個參數 | 命令列上 `\"` 被視為逸出的引號。路徑一律 `TrimEnd('\')` 後再傳 |
| 兩個 wixproj 互相收進對方的 `.wxs` | WiX SDK 以萬用字元收集同目錄 `.wxs`，`Compile Remove` 在 glob 展開前無效。一個目錄一個 wixproj |
| msi 只有 0.3 MB，內容在外部 `cab1.cab` | `Compressed="yes"` 不等於內嵌。需 `<MediaTemplate EmbedCab="yes" />` |
| Debug 組態循環相依 | 清單為空時 `<MSBuild Targets="">` 被當成預設目標而自我遞迴。改用 `Target DependsOnTargets="@(PackageArtifact)"` |
| 安裝程式 exe 的版權是 Burn 預設字串 | `Bundle` 不會沿用組件中繼資料，需明寫 `Copyright` 屬性 |

未驗證清單（依賴外部系統精確行為、無法執行驗證的項目，逐條列出，是交付物的一部分）：
- 安裝程式在乾淨的目標電腦上的實際安裝、升級、移除行為：本機已有開發環境，且安裝行為會改動系統，未實際安裝過。
- 數位簽章：未簽章的安裝程式在目標電腦會觸發 SmartScreen 警告。憑證屬於只有使用者持有的私有資產，本次不涵蓋。
- MSI 的 `UpgradeCode` 一經發佈即不得變更，本次產生的 GUID 記錄於 `Package.wxs`；它是否與既有已發佈版本衝突，取決於過往是否發佈過同名產品，本機無從查證。
