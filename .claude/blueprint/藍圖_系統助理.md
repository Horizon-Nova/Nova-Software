# 工程藍圖：Helix-Studio 系統助理

## 定性

| 問題 | 回答 |
|---|---|
| 本質是什麼 | 這台電腦上受控軟體的工作管理員：上半是全部軟體的可排序即時清單（佔用量、執行狀態、就地停用／啟動），下半是選中那一個軟體的配額工作面（一份固定欄位表，逐欄改上限、還原或套用）。對應設計稿 `SystemAssistantScreen.dc.html`。 |
| 完整生命週期是什麼 | 殼層導覽到 `assistant` → 載入受控軟體清單與固定欄位表 → 依排序鍵、搜尋字、只顯示執行中三者過濾投影出列 → 選一列成為使用中軟體 → 固定欄位表 × 該軟體的值交叉出欄位清單 → 使用者改欄位進草稿 → 套用（清空草稿、重新取樣、寫一筆事件）或還原（清空草稿）。 |
| 現有最小結構能否表達 | 不能：新增最小結構，理由：`Vaeron.HelixStudio.Shell` 是殼層本身（頂欄／圖示軌／狀態列），系統助理是掛在主內容區的一個功能單元，兩者的生命週期與資料來源不同。比照骨架「一個功能一個組件」新增 `Vaeron.HelixStudio.SystemAssistant`。 |

## 主體順序

本藍圖採用**結構順序**（由下而上：資料 → 邏輯 → 對外表面 → 繫結投影 → 顯示層），與既有三份藍圖同一種，全篇僅此一種。

## 技術規範遵循

| 規範 | 是否符合 | 說明 |
|---|---|---|
| 禁止 Interface | 不適用 | 此 repo 無 `.claude/rules/` 規範文件。沿用骨架做法：`ISystemAssistantFacade` 用 interface，`Internal/` 實作類別 `internal sealed`。 |
| DI 統一用 primary constructor | 符合 | 四層與 ViewModel 全部主建構子。 |
| VAE020／VAE021／VAE022 | 不適用 | 本次資料為記憶體內靜態種子，尚未接資料庫；接上時 view 與查詢放本組件，主表與 `DbContext` 放共用層。 |
| 資料邏輯歸屬 | 待修正 | 見 `.claude/rules/資料邏輯歸屬.md`。上述對照表（狀態呈現、熱度門檻、排序欄位與方向、篩選預設集、欄位可動狀態、度量文字）目前寫在 `SystemAssistantViewModel` 的靜態欄位，屬資料邏輯壓在專案端，須移進資料庫的對照表與 view，專案端只取投影好的列。 |
| 值域不得被塌縮成兩格 | 符合 | 每一項對映的 key 都是資料自身的值域（狀態代碼、等級名、方向名、欄位鍵），新增一個案例是插一列資料，不動結構。顯示層以資料庫給的值為 key 查外觀。 |
| 是否偏離設計稿（＝污染） | 部分偏離，逐項列出理由 | (1) 不實作 `Layout.dc.html` 新增的 `sideItems` 左側清單投影：該處 `renderVals()` 回傳恆為 `[]`、`sideEmpty` 恆為 `true`，沒有任何畫面提供內容，加一個恆空的清單不改變任何結果（§3.2）。提供內容的畫面出現時再加。(2) 不移植 `SystemAssistantScreen 配額工作站.dc.html`：`Layout.dc.html` 只 import `SystemAssistantScreen`，且該檔期待的 `sw.fields` 與字串型 `reading.net` 在 `seed/system.js` 不存在，屬已被取代的版本（§3.1 不並存）。 |
