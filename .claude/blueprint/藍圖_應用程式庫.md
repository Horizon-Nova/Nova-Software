# 工程藍圖：應用程式庫

依據模板版本：v1.1

## 0. 依據與關係

| 既有藍圖 | 關係 | 說明 |
|---|---|---|
| 藍圖_工作區管理.md | 沿用 | 沿用「目前作用中工作區」的讀取與 `WorkspaceChanged` 事件模式，本主題依此決定畫面上「已安裝」狀態要對應哪個工作區 |
| 藍圖_已安裝工具管理.md | 沿用 | 沿用其安裝／移除工具的對外能力（本主題是它的呼叫方之一），但本主題不重複其內部行為規格 |

## 1. 範圍與目的

**範圍：** 工具目錄的瀏覽（內建＋使用者匯入）、搜尋、分類篩選、匯入自訂工具、將目錄項目加入／移除目前工作區的安裝、移除自訂匯入項目。涵蓋 `AppLibraryDomain`、`AppLibraryRepository`、`BuiltInCatalogRepository`、`AppLibraryDbContext`、`AppLibraryViewModel`／`AppLibraryView`。

**目的：** 讓使用者從「隨程式出貨的內建工具」與「自行匯入的工具」這兩種來源中，挑選並安裝到目前工作區。

**不做什麼：**
- 不做工具實際安裝檔案的解壓縮／執行安裝程序（`ImportToolAsync` 只複製檔案到暫存區，不解開 zip 也不執行 msi/exe）
- 不做跨工作區的批次加入
- 不做內建工具的新增／編輯／刪除（內建工具唯讀，隨程式安裝路徑出貨）

## 2. 主軸

**目錄項目（內建或匯入）與「已安裝到某工作區」是兩件事——前者是可選清單，後者是選取結果的快照，兩者一旦建立關聯就不再互相追蹤對方的後續變動。**

判準用法：任何提案問「它讓『目錄清單』與『安裝快照』這兩層的獨立性更清楚，還是讓兩者被誤當成同一份即時同步的資料」，答不出來就不屬於這個主題。

## 3. 角色

| 角色 | 身分 | 為什麼是獨立角色 |
|---|---|---|
| A. 瀏覽／安裝操作者 | 在工具庫畫面搜尋、篩選、匯入、加入或移除工作區安裝的人 | 需要的是「找到工具、決定裝不裝」，不涉及工具本身怎麼被啟動／停止（那是 AppsManagement 的範圍） |
| B. AppsManagement（安裝目標） | 本主題透過其 Facade 執行實際安裝、移除、查已裝清單 | 本主題不持有「是否已安裝」這個狀態的真實來源，每次查詢都要向它借資料 |

**往底下／外面／之間找過的：**

| 角色 | 從哪裡冒出來 |
|---|---|
| 隨程式出貨的唯讀 Catalog 目錄（`BuiltInCatalogRepository`，路徑 `AppContext.BaseDirectory/Catalog`） | 內建工具的真實來源，執行期唯讀，掃描每個子資料夾的 `tool.json` |
| 使用者匯入暫存區（`ImportedTools` 資料夾，路徑由 `AppDataPath.LocalRoot` 決定） | 匯入工具實際檔案的落地位置，與 imported_catalog_entry 資料列分離存在 |
| 拖放事件（WPF `DragEnter`/`Drop`） | 與「匯入工具...」按鈕平行的另一個觸發路徑，只認拖放的第一個檔案 |

**收斂宣告：** 主動找過「AppLibraryFacade」這個角色——查證後確認整個專案沒有這個型別，`AppLibraryDomain` 直接被 `AppLibraryViewModel` 持有，且全專案搜尋只有 AppLibrary 自己三個檔案引用 `AppLibraryDomain`，沒有其他 Feature 消費它；這與 WorkspaceManagement／EventLog／AppsManagement 都有 Facade（因為它們被跨 Feature 呼叫）的判準一致——Facade 存在的理由是隱藏內部型別給其他 Feature，沒有其他 Feature 需要就不需要 Facade，非缺口。也找過「內建工具的版本更新機制」方向，程式碼裡內建工具版本只能隨程式整批更新（改 `tool.json`），沒有獨立更新流程，排除為新角色。無新方向。

## 4. 需求

| 角色 | 會用到 | 需要 | 工作會用到 | 想要 |
|---|---|---|---|---|
| A 瀏覽／安裝操作者 | 清單、分類篩選、搜尋、匯入（對話框／拖放）、加入工作區、更新、移除工作區安裝、移除匯入項目、展開看需求/README | 已安裝狀態要對應目前作用中工作區、內建工具不可被誤刪 | 依產線需求挑選監控／資料／維護類工具安裝 | 有更新可用時清楚看到徽章與版本號 |
| B AppsManagement | 被呼叫安裝／移除／查已裝清單 | 收到的 CatalogId／Name／Version 等欄位正確 | 無——純被動服務提供方 | 無——純被動服務提供方 |

### 對撞

| # | 衝突 | 標記 |
|---|---|---|
| 1 | 「已安裝狀態需即時反映」↔「與 AppsManagement 已裝清單的比對鍵是工具名稱字串，非穩定 id」 | 衝突——若目錄項目改名（例如同檔名重新匯入覆蓋了 Name 相同但實質不同的工具，或未來內建工具改名），已安裝快照的 `Name` 是安裝當下的複製值，不會跟著改變；比對用「目錄目前的 Name」查已裝字典，一旦兩邊字串不再相等，畫面會顯示「加入工作區」而非「已加入」，可能導致同一工具被重複安裝 |
| 2 | 「內建工具不可移除」↔「移除操作實作」 | 滿足——`RemoveImportedByCatalogIdAsync` 只查 `imported_catalog_entries` 表，內建工具的 id physically 不在這張表裡，就算繞過 UI 直接呼叫也會回傳「找不到」，是 Domain 層天然擋，不只是 UI 視覺隱藏按鈕 |
| 3 | 「匯入檔案格式/大小限制」↔「拖放與對話框兩個入口」 | 滿足——兩個入口共用同一個 `ApplyImportFileAsync` → `Domain.ImportToolAsync`，驗證邏輯只有一份 |
| 4 | 「拖放匯入」↔「一次拖放多個檔案」 | 邊界情況，非設計衝突——`OnDrop` 只取 `files[0]`，其餘檔案靜默忽略，無任何提示告知使用者只匯入了一個 |

### 對撞產生的新需求

無 —— 對撞未產生原清單外的需求，衝突 1、4 屬既有實作的現況/缺口，非新需求。

### 本質

生命週期角度：內建工具誕生於應用程式安裝當下（隨 exe 出貨），執行期唯讀，永不死亡（沒有刪除操作）；匯入工具誕生於使用者匯入動作（`version` 從 1.0.0 起跳，同名再匯入視為升版），可軟刪除。兩者的「已加入工作區」快照誕生於安裝當下的一次性資料複製（`Name`／`Version`／`Developer` 等欄位整份複製進 `installed_tool`），此後目錄項目本身的任何更新或刪除都不會回頭影響已安裝的快照——這解釋了「更新可用」徽章的判斷邏輯（比對快照 `Version` 字串與目錄目前 `Version` 字串，不同才顯示「有更新」），也解釋了衝突 1 為何會發生：唯一的關聯鍵是 `Name` 字串快照，不是穩定 id。

| 症狀 | 根因的哪一面 |
|---|---|
| 改名會讓目錄項目與已安裝快照失聯、可能重複安裝 | AppLibrary 與 AppsManagement 之間的關聯鍵統一是「工具名稱字串」而非穩定 id——這個模式在本主題是源頭（安裝時只傳 `Name` 字串過去，從未傳遞穩定的目錄項目 id），其他 Feature 依賴同一份已裝清單時會繼承這個脆弱性，但那屬於各自 Feature 自己的行為，不在本藍圖範圍內記錄 |

## 5. 功能清單

| # | 操作 | 觸發方式 | 做什麼 |
|---|---|---|---|
| 1 | 查詢分類清單 | 載入 | 回傳固定 4 類（監控／資料／維護／自訂），畫面另加「全部」 |
| 2 | 查詢工具庫清單 | 載入／切換工作區時 | 合併內建（讀 Catalog）與匯入（讀資料庫）兩種來源，依名稱排序，附目前工作區安裝狀態與版本比較 |
| 3 | 匯入工具 | 按鈕對話框／拖放檔案 | 驗證副檔名與大小上限，複製檔案到暫存區，寫入或升版 `imported_catalog_entry`；若目前有作用中工作區且同名工具已安裝，同步覆蓋安裝版本 |
| 4 | 加入工作區（含更新） | 按鈕 | 呼叫 AppsManagement 安裝，適用內建與匯入兩種來源 |
| 5 | 從工作區移除 | 按鈕（需二次確認） | 依名稱找到目前工作區的已裝實例，呼叫 AppsManagement 移除 |
| 6 | 從工具庫移除匯入項目 | 按鈕（需二次確認，僅匯入項目可用） | 軟刪除 `imported_catalog_entry`，不影響已安裝的快照 |

### 狀態

**目錄項目來源**

| 值 | 意義 | 進入條件 |
|---|---|---|
| 內建 | 隨程式出貨，唯讀 | 存在於 Catalog 目錄且有合法 `tool.json` |
| 匯入且未刪除 | 使用者自訂 | 完成一次 `ImportToolAsync` |
| 匯入且已刪除 | 從工具庫移除 | `RemoveImportedByCatalogIdAsync` 成功 |

**狀態轉換：**

| 從 | 到 | 觸發 | 不可逆 |
|---|---|---|---|
| 不存在 | 匯入且未刪除（version 1.0.0） | 首次匯入 | 否 |
| 匯入且未刪除（version N） | 匯入且未刪除（version N+1） | 同名再匯入 | 否 |
| 匯入且未刪除 | 匯入且已刪除 | 移除工具庫項目 | 是 |

| 操作 | 讀 | 寫 |
|---|---|---|
| 查詢分類清單 | 無（記憶體常數） | 無 |
| 查詢工具庫清單 | Catalog 目錄檔案系統＋`imported_catalog_entry`（未刪除）＋AppsManagement 已裝清單 | 無 |
| 匯入工具 | 來源檔案系統路徑、`imported_catalog_entry`（同名比對） | 暫存區檔案複製、`imported_catalog_entry` 新增或覆寫；若目前工作區已裝同名工具，額外呼叫 AppsManagement 安裝 |

### 對外能力

本主題無 `Facade`，`AppLibraryDomain` 即為對外能力的唯一入口，但實際上只被自己的 `AppLibraryViewModel` 消費（見第 3 段收斂宣告），故以下列出的是 Domain 的公開方法，非跨 Feature 契約：

| 能力 | 輸入 | 輸出 |
|---|---|---|
| 查詢分類清單 | 無 | `IReadOnlyList<LibraryCategorySnapshot>` |
| 查詢工具庫清單 | 目前作用中工作區 id（可為 null） | `IReadOnlyList<LibraryAppSnapshot>` |
| 匯入工具 | `ImportToolRequest` | `(success, message)` |
| 加入工作區 | catalog id、工作區 id | `(success, message)` |
| 從工作區移除 | 工具名稱、工作區 id | `(success, message)` |
| 移除工具庫項目 | catalog id | `(success, message)` |
| 訂閱異動通知 | 無（事件訂閱） | 目錄或安裝狀態發生變更時觸發 |

## 7. 失敗回饋

**失敗種類判準：重試同樣的輸入，結果會不會不同？** 會→可重試；不會→不可重試。

| 失敗 | 種類 | 使用者看到 | 呼叫方拿到 | 記事件 |
|---|---|---|---|---|
| 匯入時副檔名不支援 | 可重試（換檔案） | 「[失敗] 不支援的檔案格式，僅接受 .exe/.msi/.zip」 | `(false, message)` | 否 |
| 匯入時來源檔案不存在 | 可重試（檔案可能是暫時性地不可存取） | 「[失敗] 找不到來源檔案」 | `(false, message)` | 否 |
| 匯入時檔案超過 200MB | 可重試（換較小檔案） | 「[失敗] 檔案超過 200MB 上限」 | `(false, message)` | 否 |
| 匯入時暫存路徑解析失敗 | 依 `FileStorage.TryResolve` 失敗原因而定，多半可重試 | 該方法回傳的訊息 | `(false, message)` | 否 |
| 加入工作區找不到目錄項目（catalog id 已不存在） | 不可重試 | 「[失敗] 找不到此工具」 | `(false, message)` | 否 |
| 加入工作區時該工作區已有同名工具 | 不可重試（除非改名或移除舊有安裝） | 由 AppsManagement 回傳「[失敗] 此工作區已安裝同名工具」 | `(false, message)` | 否 |
| 從工作區移除時找不到已裝實例 | 不可重試 | 由 AppsManagement 回傳「[失敗] 此工作區未安裝此工具」 | `(false, message)` | 否 |
| 移除工具庫項目時找不到（或該項目是內建工具） | 不可重試 | 「[失敗] 找不到此工具，或它是內建工具（無法移除）」 | `(false, message)` | 否 |

**貫穿規則：** 所有失敗訊息一律以 `ResultContract.FailPrefix`（`"[失敗] "`）開頭；「加入工作區」「從工作區移除」兩個操作的實際安裝/移除邏輯與訊息內容完全委由 AppsManagement 決定，本主題只是轉呼叫，不重新包裝訊息。

## 9. 行為規格

> 逐項對應第 5 段，數量一致。

### 對應第 5 段第 1 項：查詢分類清單

| 情境 | 條件 | 該發生什麼 |
|---|---|---|
| 正常 | 恆定 | 回傳寫死的 4 類，畫面另加「全部」 |

### 對應第 5 段第 2 項：查詢工具庫清單

| 情境 | 條件 | 該發生什麼 |
|---|---|---|
| 正常 | Catalog 目錄與匯入項目皆存在 | 合併兩者，依名稱排序，附安裝狀態 |
| 異常 | Catalog 目錄不存在（理論上不應發生，隨程式出貨） | `BuiltInCatalogRepository` 回傳空清單，不擲例外 |
| 異常 | 某 `tool.json` 格式錯誤或欄位缺失 | 該筆解析為 null，直接跳過，不中斷其餘項目的載入 |
| 邊界 | 目前無作用中工作區 | 已安裝狀態全部視為未安裝（安裝字典為空） |
| 邊界 | Catalog 資料夾內某工具的 `.exe` 實體檔不存在 | `FileSize` 以 0 計算，不擋顯示，也不驗證使用者是否真能執行 |

### 對應第 5 段第 3 項：匯入工具

| 情境 | 條件 | 該發生什麼 |
|---|---|---|
| 正常 | 合法檔案、無同名項目 | 建立新項目，version 1.0.0 |
| 正常 | 合法檔案、已有同名未刪除項目 | 覆寫該項目內容，version 修訂號 +1 |
| 正常 | 有作用中工作區且同名工具已安裝 | 匯入完成後額外呼叫安裝，覆蓋安裝版本 |
| 異常 | 副檔名不支援／來源不存在／超過大小上限 | 擋下，不寫入任何資料 |
| 邊界 | 版本號格式不是三段式數字（例如手動塞入非標準格式） | `BumpPatchVersion` 解析失敗時重置為 `"1.0.0"`，不擲例外 |
| 邊界 | 一次拖放多個檔案 | 只匯入第一個，其餘無提示忽略 |

### 對應第 5 段第 4 項：加入工作區（含更新）

| 情境 | 條件 | 該發生什麼 |
|---|---|---|
| 正常 | 目錄項目存在（內建或匯入） | 呼叫 AppsManagement 安裝，成功後畫面依 `Changed` 事件刷新 |
| 異常 | catalog id 已不存在於兩種來源 | 回傳「找不到此工具」 |
| 異常 | 該工作區已安裝同名工具 | 依 AppsManagement 規則擋下（見其藍圖） |

### 對應第 5 段第 5 項：從工作區移除

| 情境 | 條件 | 該發生什麼 |
|---|---|---|
| 正常 | 使用者確認對話框 | 依名稱找到已裝實例並移除 |
| 取消 | 使用者取消確認對話框 | 不執行任何動作 |
| 異常 | 該工作區未安裝此工具（名稱查無） | 回傳「此工作區未安裝此工具」 |

### 對應第 5 段第 6 項：從工具庫移除匯入項目

| 情境 | 條件 | 該發生什麼 |
|---|---|---|
| 正常 | 使用者確認對話框，項目為匯入來源 | 軟刪除，畫面刷新 |
| 取消 | 使用者取消確認對話框 | 不執行任何動作 |
| 異常 | catalog id 是內建工具或已不存在 | 回傳「找不到此工具，或它是內建工具（無法移除）」，不區分這兩種原因 |

**跨操作互動：** 匯入與加入工作區之間沒有鎖定機制；單一 UI 執行緒下不構成真實並發問題。

## 10. 判準

| 判準 | 適用情境 |
|---|---|
| 沒有其他 Feature 消費 `AppLibraryDomain` 時，不需要建立 Facade 包裝層 | 任何討論「是否要幫 AppLibrary 補一個 Facade」的前提 |
| 目錄項目與已安裝快照的關聯鍵是工具名稱字串，一旦目錄項目改名會與既有安裝快照失聯 | 任何討論「加入工作區」按鈕狀態為何與實際安裝情形不符的除錯起點 |
| 內建工具的移除限制是 Domain 層資料表結構天然形成的（內建工具根本不在 `imported_catalog_entries` 表），不是額外寫的權限檢查 | 判斷這道限制能否被繞過時的依據 |
| 匯入工具的「同一個工具」判定依據是檔名去除副檔名後的字串，不是使用者輸入的任何識別碼 | 討論「重新匯入是新增還是升版」時的依據 |

## 11. 驗收條件

| # | 條件 | 怎麼證明 |
|---|---|---|
| 1 | 建置通過 | `dotnet build` 對 `Vaeron.HelixStudio.sln` 成功 |
| 2 | 內建與匯入工具合併顯示且排序正確 | 手動操作：匯入一個工具，預期清單依名稱排序後與內建工具混合顯示 |
| 3 | 同名再匯入會升版而非新增 | 手動操作：匯入同檔名檔案兩次，預期第二次版本號修訂號 +1，清單筆數不變 |
| 4 | 內建工具無「移除」按鈕，匯入工具有 | 手動操作：檢視表格操作欄，內建工具列不應出現「移除」按鈕 |
| 5 | 切換工作區後安裝狀態徽章正確刷新 | 手動操作：在工作區 A 安裝某工具後切到工作區 B，預期該工具顯示為未安裝 |
