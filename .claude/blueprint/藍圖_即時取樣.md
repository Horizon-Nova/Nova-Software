# 工程藍圖：Helix-Studio 即時取樣

## 定性

| 問題 | 回答 |
|---|---|
| 本質是什麼 | 一個常駐的採集迴圈：依一份「度量來源表」逐列向 Windows 取值，把每個受控軟體目前的實際佔用寫回主表。畫面只是讀主表，不知道值從哪來。 |
| 完整生命週期是什麼 | App 啟動 → 採集器啟動 → 每隔設定的秒數 → 為每個受控軟體解析出它目前的行程集合 → 對每個度量依其來源取值並聚合 → 寫回 `software_reading` → 畫面重取投影。 |
| 現有最小結構能否表達 | 不能：新增最小結構，理由：`software_reading` 目前是靜態種子，沒有任何寫入路徑；且寫入主表的東西不得藏在功能組件內（VAE021／VAE022 的位置要求），需要一個共用層組件。 |

## 主體順序

本藍圖採用**結構順序**（由下而上：來源定義 → 行程比對 → 採集 → 寫回 → 畫面刷新），與既有藍圖同一種，全篇僅此一種。

## 骨架

| 順序 | 項目 | 內容 |
|---|---|---|
| 1 | `metric_source` | 每個度量從哪裡取。`provider` 的值域是取得方式（`perfcounter`／`etw`），`expression` 是該方式所需的字串。新增一個度量或一種來源都是插一列，採集器結構不動。 |
| 2 | `process_match` | 一個受控軟體對應哪些行程。`match_kind` 的值域是比對方式（`executable_path`／`process_name`），`pattern` 是該方式的樣式。一個軟體可有多列，Chrome 的數十個行程聚合成一列讀數。 |
| 3 | `machine_info` | 邏輯處理器數。效能計數器給的 CPU 百分比是相對單核，除以此數才是工作管理員顯示的值。 |
| 4 | `sampling` | 取樣間隔秒數。 |
| 5 | `Shared/Vaeron.HelixStudio.Sampling` | 共用層組件：`ISamplerFacade`（啟動、停止、立即取樣一次）、`Internal/` 放各 provider 的取值方式與寫回。寫入主表，故不在功能組件內。 |
| 6 | 寫回 | `software_reading` 存的是 Windows 給的原始值，不做換算。CPU 除以核心數在 view 完成——核心數變動時不必重採。 |
| 7 | 畫面刷新 | 採集完成後通知，系統助理重取一次投影。 |

## 技術規範遵循

| 規範 | 是否符合 | 說明 |
|---|---|---|
| 資料邏輯歸屬 | 符合 | 見 `.claude/rules/資料邏輯歸屬.md`。度量從哪取、軟體對應哪些行程、取樣多久一次、CPU 怎麼換算，全部是表與 view；專案端只執行取值與寫回。 |
| 值域不得被塌縮 | 符合 | `provider` 與 `match_kind` 都是資料自身的值域，採集器以它們為 key 查取值方式，新增一種來源多一列。 |
| 禁止 Interface | 不適用 | 此 repo 無 `.claude/rules/` 的 Interface 規範。沿用骨架做法：`ISamplerFacade` 用 interface，`Internal/` 實作 `internal sealed`。 |
| DI 統一用 primary constructor | 符合 | 各層皆主建構子。 |
| 是否偏離設計稿 | 無可對照 | 設計稿的取樣是 `wait(700)` 的假延遲，沒有交代真實來源。本藍圖的來源全部取自實測（見驗收）。 |

## 驗收

| 項目 | 分析（我推導） | 驗證（外部系統實際跑過） |
|---|---|---|
| Windows 提供哪些 per-process 度量 | — | 已驗證：`Get-Counter -ListSet Process` 有 `% Processor Time`／`Working Set`／`IO Data Bytes/sec`；**沒有任何 per-process 網路計數器**，全部網路計數器皆為每張網卡或全系統 |
| 網路須改用 ETW | — | 已驗證：`logman query providers` 列出 `Microsoft-Windows-Kernel-Network`，GUID `{7DD42A49-5329-4832-8DFD-43D979153A88}` |
| CPU 百分比須除以核心數 | 計數器為相對單核 | 已驗證：本機 `Environment.ProcessorCount` = 8；實測 chrome `% Processor Time` = 1.55 |
| 計數器可實際讀出 | — | 已驗證：chrome `Working Set` = 204521472 bytes |
| 畫面數字隨真實佔用變動 | — | 待執行 |
| 一個軟體的多個行程正確聚合 | — | 待執行 |

未驗證清單（依賴外部系統精確行為、無法執行驗證的項目，逐條列出，是交付物的一部分）：
- ETW session 需要管理員權限。未提權時 session 建立會失敗，網路度量將寫入 NULL 並在畫面顯示 N/A；此路徑本機未在非管理員身分下實測過。
- `Microsoft.Diagnostics.Tracing.TraceEvent` 3.2.5 對 .NET 10 的相容性未實測，建置後才知道。
- 工廠現場的軟體實際安裝路徑與行程名稱與本機不同，`process_match` 的樣式須依現場調整；本機只能以本機已安裝的軟體驗證比對機制本身。
