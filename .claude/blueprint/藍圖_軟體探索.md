# 工程藍圖：Helix-Studio 軟體探索

## 定性

| 問題 | 回答 |
|---|---|
| 本質是什麼 | 清單本身來自 Windows。每輪取樣先列舉這台機器上實際存在的行程，把觀測到的事實寫進資料庫；`software` 是機器現況的鏡子，不是預先寫好的名單。 |
| 完整生命週期是什麼 | 採集器每輪 → 列舉行程並讀出每個行程的檔名、產品名、發行者、版本、路徑、有無視窗、工作階段 → 寫入 `process_seen` → 以集合運算併入 `software`（新出現者新增、本輪見到者標 running、未見到者標 stopped）→ 取讀數 → 畫面重取投影。 |
| 現有最小結構能否表達 | 不能：`software` 目前是六列固定種子（設計稿的示意資料），`process_match` 是人工猜的樣式。兩者都是把「機器上有什麼」寫死在專案裡，屬結構選錯，依 §4.1 整份重寫 schema。 |

## 主體順序

本藍圖採用**結構順序**（由下而上：觀測 → 併入 → 命名 → 取值 → 顯示），與既有藍圖同一種，全篇僅此一種。

## 骨架

| 順序 | 項目 | 內容 |
|---|---|---|
| 1 | `process_seen` | 一輪觀測的原始結果，每個行程檔名一列。採集器每輪清空重寫。欄位全是 Windows 直接給的事實，取不到者為 NULL。 |
| 2 | `software` | 一個行程檔名一列，`id` 即檔名。同名的多個行程（Chrome 開幾個視窗都是 `chrome`）聚合成同一列，與工作管理員的分組一致。新出現者新增，出現過的不刪除——`state` 由 `stopped` 承載「曾經跑過、現在沒跑」。 |
| 3 | 併入 | 三道集合運算：`INSERT ... WHERE id NOT IN (process_seen)`、`UPDATE ... WHERE id IN (process_seen)` 設 running、`UPDATE ... WHERE id NOT IN (process_seen)` 設 stopped。沒有逐列判斷。 |
| 4 | `v_software_name` | 顯示名稱從候選中依序取第一個非 NULL：產品名 → 行程檔名。候選以 UNION 排成一張表，`ORDER BY rank LIMIT 1`，形狀與 `heat_band` 同。新增一種命名來源＝多一行 UNION。 |
| 5 | `v_software_system_value` | 系統回報的唯讀欄位（版本、安裝路徑）由 `software` 的欄位直接供給，不寫進 `software_value`。`software_value` 只裝使用者設定的值。新增一個系統欄位＝多一行 UNION。 |
| 6 | 取樣目標 | `v_sampling_target` 直接以 `software.id` 當效能計數器的 instance 基底名，`process_match` 整張刪除——比對規則就是「檔名相同」，不需要另一張表承載。 |
| 7 | 配額欄位 | 探索出來的軟體沒有人設過配額，`software_value` 全為 NULL，畫面顯示 N/A。這是正確結果，不是缺漏。 |
| 8 | `reading` | 機器與軟體的讀數同一張表，`scope_id` 為軟體 id 或 `machine`。採集器不認得兩者的差別，`v_sampling_target` 以 UNION 把兩種列並成一份工作清單。 |
| 9 | 摘要 | 頂部的 CPU／記憶體／網路取自 `machine` 的讀數，是 Windows 量出來的機器用量，不是把清單各列加起來。加總永遠等不到系統值，且會隨過濾條件變動。 |

## 技術規範遵循

| 規範 | 是否符合 | 說明 |
|---|---|---|
| 資料邏輯歸屬 | 符合 | 見 `.claude/rules/資料邏輯歸屬.md`。C# 只做一件事：把 Windows 給的欄位原樣塞進 `process_seen`。誰是新軟體、誰在跑、叫什麼名字，全部是 SQL 的集合運算與 view。 |
| 值域不得被塌縮 | 符合 | `session_kind`、`has_window` 是 Windows 自身的值域，以欄位保留，不轉成專案端的布林判斷。要不要據此過濾是日後多插一列的事。 |
| NULL 即 N/A | 符合 | Windows 取不到的欄位（無權限讀取的行程沒有路徑與版本）綁定 NULL，不以空字串代替。 |
| 是否偏離設計稿 | 偏離且為修正 | 設計稿的六列是示意資料。此螢幕的目的是即時監測這台機器，示意資料留在產品裡即為假資料。 |

未驗證清單（依賴外部系統精確行為、無法執行驗證的項目，逐條列出，是交付物的一部分）：
- 以非管理員身分執行時，部分行程的 `MainModule` 讀取會擲例外，該行程的路徑與版本將為 NULL。哪些行程屬此類依權限而定，未逐一實測。
- 行程檔名與效能計數器 instance 名在含 `#` 的重名情形下如何對應，已在 `PerfCounterProvider` 以 `name` 與 `name#n` 兩段涵蓋，但未在有重名的機器上實測。
- 「停用」目前只改資料庫的 `state`，不動真實行程，下一輪探索會把它改回「執行中」。設計稿寫的是「不論是否當掉，強制結束」，該通道尚未接上。
- 網路整列為 N/A：`provider_status.etw` 為不可用，per-process 與機器整體皆無值。
