# SandBox 研究結果：硬體層在非提權下能回答到什麼程度

以 ctypes 直接綁定 SetupAPI 與 cfgmgr32，綁定形狀與 C# P/Invoke 一對一對應；
SMBIOS 與效能計數器走 CIM。全部在非提權工作階段執行。

欄位清單見 `.claude/rules/硬體事實取得.md`。

## 模組

| 模組 | 內容 |
|---|---|
| `cim.py` | CIM／WMI 橋接。明設 UTF-8：主控台預設以 ANSI 輸出，含非 ASCII 欄位時整批解碼失敗 |
| `hwsurvey.py` | 46 個 CIM 類別的普查：各回幾列、哪些拒絕存取 |
| `hwdump.py` | 25 個來源的實測值，逐欄標示有值與無值 |
| `setupapi.py` | SetupAPI 裝置樹綁定：`SetupDiGetClassDevs`／`SetupDiEnumDeviceInfo`／`SetupDiGetDevicePropertyKeys`／`SetupDiGetDevicePropertyW`／`CM_Get_DevNode_Status` |
| `devicedump.py` | 401 個裝置的完整屬性、拔除紀錄、USB 樹、驅動提供者分布 |
| `handles.py` | 系統控制代碼表綁定：`NtQuerySystemInformation`／`DuplicateHandle`／`NtQueryObject` |
| `deviceuse.py` | 誰開著哪個檔案或裝置的實測涵蓋率 |
| `audiosession.ps1` | 哪個軟體正在用哪個音訊裝置。COM 介面配置與 C# 端一對一對應 |

輸出：`devices.json`（401 個裝置的全部屬性）。

## 發現

### 一　裝置樹是硬體層的主表，不是 WMI

`Win32_PnPEntity` 回 194 列，`Get-PnpDevice` 回 401 列。差的 207 列是**曾經接過、現在不在**的裝置。

而且沒有一個 WMI 類別帶得出這三個欄位：`Device_LastArrivalDate`、`Device_LastRemovalDate`、`Device_Parent`。它們只在 SetupAPI 的 DEVPKEY 屬性存放區裡。

「這台機器上插過什麼」這個問題，WMI 答不出來。

### 二　執行時狀態不在屬性存放區

`SetupDiGetDevicePropertyKeys` 對 401 個裝置只有 2 個回報 `DEVPKEY_Device_IsPresent`，`ProblemCode` 則全為 0。

屬性存放區只保存靜態屬性。在不在線、問題碼、狀態旗標三者須走 `CM_Get_DevNode_Status`：

```
CM_Get_DevNode_Status(&status, &problem, DevInst, 0)
   回傳碼 CR_SUCCESS → 在線；其餘 → 不在線
   status 的位元即 DN_STARTED／DN_DRIVER_LOADED／DN_REMOVABLE／DN_HAS_PROBLEM
```

改走這條路後，194／207 的在線與不在線比例與 `Get-PnpDevice` 一致。

### 三　逐屬性查詢的成本差三個數量級

`Get-PnpDevice | Get-PnpDeviceProperty -KeyName <14 個鍵>` 對 401 個裝置在十分鐘內未回。
同一批資料以 ctypes 直接列舉：**1.67 秒**。

`Get-PnpDeviceProperty` 一次只問兩個鍵時可用（802 筆），問十四個鍵時輸出為空且結束碼為 0——
無錯誤訊息可據以判斷，屬不可靠路徑。

### 四　一次插拔在裝置樹留下多列

一支 SanDisk 隨身碟的完整軌跡：

```
2026-07-31 09:48:10  插上  USB\VID_0781&PID_55AB\0401704D...          USB Mass Storage Device
2026-07-31 09:48:10  插上  USBSTOR\DISK&VEN__USB&PROD__SANDISK_3.2GEN1  USB SanDisk 3.2Gen1 USB Device
2026-07-31 09:48:10  插上  SWD\WPDBUSENUM\_??_USBSTOR#DISK&VEN__USB...  E:\
2026-07-31 09:48:10  插上  STORAGE\VOLUME\_??_USBSTOR#DISK&VEN__USB...  磁碟區
2026-07-31 13:16:35  拔除  以上四者
```

USB 裝置、儲存裝置、磁碟區、可攜裝置各一列。以列數計會把一支隨身碟算成四台。
`Device_ContainerId` 是把它們併回同一台實體裝置的鍵——與網路層以實體位址併裝置同一種形狀。

拔除紀錄本機共 74 筆，最舊為 2026-06-19。

### 四之二　401 列是 31 台裝置

以 `Device_ContainerId` 分組：32 個不同容器識別，扣掉萬用容器 `{00000000-0000-0000-ffff-ffffffffffff}`
（「不屬於任何實體裝置」的保留值）後為 **31 台**。

```
12 列  {a119fd67-...}  G733 / HID-compliant device / Logitech Blue VO!CE Effect
11 列  {389b9f50-...}  XROUND AERO PRO / Airoha_APP / BTNOTIFYR
11 列  {ed4eb7cb-...}  HID Keyboard Device / HID-compliant mouse / …
 8 列  {84950890-...}  Xbox Wireless Controller / HID-compliant game controller / 泛型存取設定檔
```

一副耳機由 12 列組成。與網路層「72 筆芳鄰記錄實為 6 台裝置」同一種形狀：
以列數計即為錯，主鍵必須是實體裝置的身分。

### 五　埠位置有兩種表達，不可互推

```
LocationInfo   Port_#0005.Hub_#0002
LocationPaths  PCIROOT(0)#PCI(1400)#USBROOT(0)#USB(5)
               ACPI(_SB_)#ACPI(PC00)#ACPI(XHCI)#ACPI(RHUB)#ACPI(HS05)
```

`LocationInfo` 對 401 個裝置只有 114 個有值，`LocationPaths` 有 199 個。
複合裝置的子介面其 `LocationInfo` 形如 `0000.0014.0000.005.000.000.000.000.000`，與父裝置的
`Port_#0005.Hub_#0002` 不同格式。要回答「插在機殼哪一個孔」須靠 `LocationPaths` 的 `USB(n)` 段。

### 六　驅動簽章者只有兩種值，不是廠商

`Win32_PnPSignedDriver` 196 列中 194 列已簽章，`Signer` 的值域只有：

```
157  Microsoft Windows
 37  Microsoft Windows Hardware Compatibility Publisher
```

那是 WHQL 交叉簽章，不是驅動廠商。廠商在 `Device_DriverProvider`（Logitech、Intel Corporation、NVIDIA…）。
判定依據只能是「有沒有簽」，不能是「誰簽的」。

本機兩個未簽章項目為 `G733` 的 LampArray 介面與 `HTREE\ROOT\0`（裝置樹根）。

### 七　同一個事實，兩條路徑的權限不同

| 事實 | 提權路徑 | 免提權路徑 |
|---|---|---|
| Secure Boot | `Confirm-SecureBootUEFI` → 拒絕存取 | 登錄 `SecureBoot\State\UEFISecureBootEnabled` → 1 |
| TPM 存在 | `Get-Tpm` → 回空欄位 | 裝置樹 `ACPI\MSFT0101\1` → Trusted Platform Module 2.0 |
| 韌體型別 | UEFI 變數 → 需提權 | `firmware_type` 環境變數 → UEFI |

`Get-Tpm` 在非提權下不擲錯，回的是**空欄位**。照字面讀會得到「沒有 TPM」的錯誤結論。

### 八　溫度在非提權下完全取不到

```
MSAcpi_ThermalZoneTemperature      拒絕存取
Win32_TemperatureProbe             2 列，Status=OK，CurrentReading=NULL
Win32_Fan                          3 列，Status=OK，DesiredSpeed=NULL
MSFT_StorageReliabilityCounter     拒絕存取（含硬碟溫度、通電時數、耗損）
```

`Win32_TemperatureProbe` 與 `Win32_Fan` 的列存在且狀態為 OK，但讀值欄位為 NULL——
類別有列不代表有值。

### 九　GPU 有每行程的使用率

```
\GPU Engine(pid_25988_luid_0x00000000_0x000123fc_phys_0_eng_0_engtype_3d)\Utilization Percentage
\GPU Adapter Memory(luid_0x00000000_0x000123fc_phys_0)\Dedicated Usage   4629467136
```

實例名稱含行程識別，可與軟體主題對接。636 個實例中 17 個非零。

`Win32_VideoController.AdapterRAM` 為 32 位元欄位，RTX 4060 的 8 GB 回 4293918720——超過 4 GB 的顯示卡此欄不可用。

### 十　EDID 欄位是位元組陣列不是字串

`WmiMonitorID` 的四個識別欄位皆為 `UInt16[16]`，須去掉補零後逐位元組轉字元：

```
ManufacturerName [71,66,84,0,...]      → GBT
ProductCodeID    [50,55,49,70,0,...]   → 271F
UserFriendlyName [71,83,50,55,81,67,0] → GS27QC
SerialNumberID   [50,52,50,54,...]     → 24265B002954
```

### 十一　拒絕存取的六個來源

```
root/wmi/MSStorageDriver_FailurePredictStatus            SMART 健康預測
root/wmi/MSStorageDriver_FailurePredictData              SMART 原始屬性
root/wmi/MSStorageDriver_ATAPISmartData                  SMART ATA 資料
root/wmi/MSAcpi_ThermalZoneTemperature                   ACPI 熱區溫度
root/microsoft/windows/storage/MSFT_StorageReliabilityCounter  通電時數、耗損、溫度
root/cimv2/security/microsoftvolumeencryption/Win32_EncryptableVolume  磁碟加密狀態
```

其餘 40 個類別全部可用。

## 第二輪：填滿未驗證清單

### 十二　USB 音訊裝置可回答「誰在用」，輸入裝置不行

`IAudioSessionManager2` 對每個音訊端點列出工作階段，每個工作階段帶行程識別與使用中狀態：

```
[輸出] 喇叭 (Logitech G733 Gaming Headset)      ← USB 裝置
           pid=15860 (parsecd)      使用中
           pid=16044 (explorer)     非使用中
           pid=21140 (wallpaper32)  非使用中
[輸入] Microphone (Logitech G733 Gaming Headset)
           pid=0    (系統音效)      非使用中
```

`IAudioSessionControl2` 繼承 `IAudioSessionControl` 的九個方法，其後才是自己的五個。
介面宣告前面少算一格會使 `GetProcessId` 回垃圾值**而不報錯**——實測回過 `state=1015788528`。

USB 輸入裝置（滑鼠、鍵盤）仍無法回答：其控制代碼由 SYSTEM 身分的行程持有。

### 十三　驅動表只涵蓋在線裝置

`Win32_PnPSignedDriver` 195 列與裝置樹 401 列的差集為 208 個，實測**全部為不在線的裝置**，
在線而無驅動列者 0 個。

### 十四　磁碟機代號與裝置路徑的對應

```
QueryDosDeviceW("C:")  →  \Device\HarddiskVolume4
QueryDosDeviceW("D:")  →  \Device\HarddiskVolume1
```

控制代碼表回的是 `\Device\HarddiskVolumeN\...`，要換成使用者看得懂的路徑須靠此對應。

### 十五　命令列的可讀範圍是身分邊界，不是權限邊界

```
本使用者的行程 101 個   有 CommandLine 97 個
其他身分的行程 154 個   有 CommandLine  0 個
```

非提權下對他人身分的行程一個都讀不到，不是部分讀不到。

### 十六　對照資料的實測命中率

| 資料 | 授權 | 更新 | 規模 | 本機命中 |
|---|---|---|---|---|
| `usb.ids` | GPL v2+ 或 3-clause BSD | 每日快照 | 廠商 3427、產品 20537 | 廠商 16/16、產品 8/16 |
| `pci.ids` | 同上 | 每日快照 | 供應商 2511、裝置 21427 | 供應商 37/37、裝置 37/37 |
| IANA 埠 | 未取得 | 未取得 | 有名稱者 11499 組 | 依連線數 59%、依埠種類 8/208 |
| IEEE OUI | 未取得（取得端回 418／403） | 未取得 | 39941 列 | 3/3 台同網段裝置 |

`usb.ids` 查不到 `046D:0AFE`（G733）、`04D9:A31C`（滑鼠）、`0781:55AB`（SanDisk）的產品名，只查得到廠商。
缺產品名時以 `Device_BusReportedDeviceDesc` 遞補，該欄 401 個裝置中 161 個有值。

`pci.ids` 對本機 37 種 PCI 裝置全部命中，含 `10DE:2882` → GeForce RTX 4060。

IANA 埠的兩個涵蓋率差距極大：443 一個埠就佔 2876 條連線，
其餘 200 種皆為對方的臨時埠，本來就不該有服務名稱。
