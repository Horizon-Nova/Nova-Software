# VNCSCP 工程藍圖

## 目的

RD 現場人員在一台 Windows 工作站上管理數十台裝有 VNC 伺服器的機台：登錄機台連線資料、確認每台目前連得上與否、把同一份檔案或資料夾批次送到選定的機台、事後追查每一次操作與傳輸的結果。

一個視窗、一頁主畫面完成上述全部動作；事件日誌的完整查詢與匯出走次視窗。

## 名詞

| 名詞 | 是什麼 |
|---|---|
| 連線 | 一台機台的連線資料：名稱、IP、Port、VNC 密碼、所屬群組、上次測試結果 |
| 群組 | 連線列上的一個文字標籤。不是獨立實體，沒有自己的生命週期，第一次被打上即成立，最後一筆被移除即消失 |
| 連線狀態 | 上次測試的結果，不是「現在連不連得上」 |
| 任務 | 一次批次部署提交。活在畫面上，不持久化，關掉程式即消失 |
| 部署歷史 | 每一次真正送出的傳輸嘗試留下一列。自動重試與手動重試各留一列 |
| 事件 | 任何操作留下的一筆紀錄：等級、來源、訊息、明細、關聯連線 |

## 資料

單一 SQLite 檔案 `%LOCALAPPDATA%\VNCSCP\app.db`，一個主題一份 DbContext，三張主表。

| 主表 | 欄位 |
|---|---|
| `connection` | id, name, ip, port, password_cipher(BLOB), status, last_tested_at, last_test_message, created_at, is_deleted, group_name(nullable) |
| `event_log` | id, occurred_utc_ticks, level, source, message, detail, related_connection_id(nullable) |
| `deployment_history` | id, deployed_ticks, connection_id, target_name, target_ip, local_path, remote_path, success, message, operated_by |

索引：`event_log(occurred_utc_ticks)`、`event_log(related_connection_id)`、`deployment_history(deployed_ticks)`。

功能端一律讀 View，不讀主表：

| View | 內容 |
|---|---|
| `Vw_Connection` | `connection` 去掉 `is_deleted = 1` 與 `password_cipher` 以外全欄 |
| `Vw_EventLog` | `event_log` 全欄 |
| `Vw_DeploymentHistory` | `deployment_history` 全欄 |

寫入走主表，讀取走 View；View 為無主鍵型別，寫不回去，讀寫分離由型別保證。

結構來源是打包的 SQL 結構定義檔，不由 C# 型別推導產生。啟動時讀取 `connection` 表目前實際存在的欄位，依這個形狀決定要套用哪幾份定義檔——資料庫自己的形狀就是狀態，不另外維護版本號。整批套用在同一個交易內完成，中途失敗整批回復。

密碼以 DPAPI CurrentUser 範圍加密後存 `password_cipher`。明文只在需要當下解出，裝在會歸零的緩衝區裡，用畢立即釋放。解密失敗是可恢復的流程，不使程式無法啟動。

## 每個功能的職責

### 連線管理

對外提供：連線清單、群組名稱清單、新增／更新／刪除連線、解出單筆密碼明文、測試單筆連線、群組更名、取消群組。任何寫入完成後對外發一個「有變動」訊號。

同時作為部署目標的提供方：交出可選目標清單、依連線識別碼解出密碼。

測試連線＝純 RFB 協定交握，不開任何 UI。流程：TCP 連上（逾時三秒）→ 交換版本橫幅 → 取得安全類型清單 → 選 VNC Authentication → 收 16 位元組挑戰 → 以密碼推出的 DES 金鑰回應 → 讀安全結果。每一步附上時間戳寫進診斷字串，成為事件明細。

狀態值域：

| 狀態 | 何時 |
|---|---|
| 未知 | 從未測試 |
| 可連線 | 安全結果為成功 |
| 密碼錯誤 | 過了安全交握，安全結果回報失敗 |
| 被鎖定 | 安全交握前或中就被拒（伺服器節流） |
| 無法連線 | TCP 逾時或被拒 |

測試的回傳語意：操作本身是否完成，與機台是否可達，是兩件事。TCP 逾時、密碼錯誤都屬「操作成功、結果不可達」；只有解密失敗這種本端問題才算操作失敗。

群組操作的真實形狀：更名＝把該名稱的所有連線改標新名稱；取消群組＝把該名稱的所有連線改為未分組，連線本身不刪。群組清單＝目前正被使用的名稱去重。

### 事件日誌

對外提供：依條件查詢事件清單、批次取多筆連線各自最近 N 筆事件、依當前條件匯出 JSON。任一筆事件被記錄後發一個「有變動」訊號。

同時作為事件記錄的提供方。記錄失敗不得阻斷呼叫方的業務流程。

查詢條件：關鍵字（比對來源與訊息）、時間範圍（全部／今日／近七日／近三十日）、等級（一般／警告／錯誤）。單次上限 500 筆，最新在前。

批次取近期事件以單一查詢完成，先以有界上限撈候選再依連線分組各取前 N 筆，不逐列各自查詢。

匯出為 JSON，中文原樣不轉義，等級輸出文字，帶 BOM。寫檔失敗把平台給的原因原樣帶到狀態列。

### 批次部署

對外提供：部署歷史清單、上次使用的路徑、提交任務、單台重試、整批取消、查某連線最近一次進度。每一台的進度變化各發一則通知，呼叫方只更新對應那一列。

提交＝驗證＋記住路徑＋解析目標名單＋排入佇列。驗證項：至少勾一台、來源與遠端路徑皆非空、排程時間須晚於現在。驗證失敗不產生任務。

派發：排程時間為空或已過即刻排入；未來時間先進排程等待區，每秒掃描，時間到才排入佇列。取消整批時，排程等待中與佇列中的機台一併取消。

執行：以「單一機台」為工作單位跨機台有界併發，上限來自設定檔，不寫死。每台最多嘗試三次，失敗之間退避等待且等待期間可被取消打斷。單台失敗不影響其他台。每次嘗試結束寫一列部署歷史與一則事件。

傳輸＝RFB File Transfer 純協定，不開檢視器、無視窗。單一檔案直送；資料夾先打包成 zip 再送，zip 內部項目名與遠端路徑用伺服器 ANSI 碼頁而非 UTF-8。序列：交握認證 → 設定遠端目錄 → 排空目錄列表 → 提出檔案 → 等接受 → 分塊送出 → 結束標記。

上次使用的路徑存在本功能自己的一個小 JSON 檔，不混進共用設定。

### 主畫面

不持有自己的資料，也沒有自己的持久化狀態。把三個功能的對外入口組合成一份逐列快照：連線本身＋該台的部署狀態＋該台的近期事件。

三個來源之中只有連線清單是整頁顯示的先決條件；事件查詢失敗只讓自己那一格空白，不擋連線清單與部署狀態。

畫面上的動作：

| 動作 | 落到哪 |
|---|---|
| 搜尋、只看異常 | 條件送進查詢，畫面只顯示查回來的結果 |
| 依群組分段顯示 | 清單控制項依 View 給的群組欄位分段 |
| 展開一列 | 帶出可編輯欄位與該台密碼明文、近期事件、部署狀態 |
| 新增／儲存編輯／刪除 | 連線管理 |
| 勾選後：測試已選／刪除已選／部署已選 | 連線管理／批次部署 |
| 群組面板：行內更名、取消群組 | 連線管理 |
| 部署面板：來源路徑、遠端路徑、可選排程時間 | 批次部署 |
| 任務彙總列：進度、失敗清單、整批重試、取消 | 批次部署 |
| 開啟事件日誌 | 次視窗導覽 |

刪除連線與取消群組要先過確認框。每個操作的結果落在狀態列，只顯示最後一筆。

整批重查時就地套用：既有列只換快照，只新增或移除真正有變動的列。單台部署進度變化直接改那一列，不整批重查。

任務彙總只記彙總、失敗清單與提交時間；逐台明細已呈現在主表格各列，不重複。保留上限二十筆，超出的已完結任務先被丟棄。

## 貫穿規則

**資料邏輯歸資料庫。** 分類、衍生欄位、顯示文字、篩選條件一律由主題萬用表上的 View 或參數化查詢承載；程式端只收資料、只讀欄位。狀態文字、群組顯示名、時間顯示、成功文字都是 View 的欄位，不在程式端再算一次。新增一種顯示需求時改的是 View，不是程式。

**成敗由型別承載。** 結果型別對外只給兩種序列：成功時帶值、失敗時帶訊息，兩者互斥且其一為空。呼叫端只描述成功那條路，失敗自己流過去。外部世界的一次判定收進結果型別的入口只有一處。

- 例外不在功能層攔截。會擲出的工作交給共用的收斂入口，由它轉成結果型別；沒有呼叫方可接收結果的位置（事件處理常式、計時器回呼、背景工作、收尾清理）用守衛承接。
- 對外簽名不並排多個裸原始型別，包成具名型別。
- 可能失敗的操作回傳結果型別，不以例外當回傳路徑。
- 事件訂閱必有配對解除。
- 密碼明文不快取、不轉字串留存、用畢歸零。
- SQL 一律參數化。

## 前端

視覺設計沿用既有 XAML 與資源字典（色票／字型／控制項樣式／圖示幾何／可顯示密碼框），程式碼的繫結名稱、事件處理常式名稱、資源鍵對齊該批 XAML。正式設計圖委託完成後整批替換。

## 未驗證的推測

- 跨機台併發上限預設值適用於現場的機台規模與網路頻寬。
- RFB File Transfer 的序列針對 UltraVNC 的實作；其他 VNC 伺服器是否接受同一序列未查證。
- 遠端路徑編碼採伺服器 ANSI 碼頁，前提是伺服器與本機同一地區設定。
