# 前端 需求單（VaeronInSpecDemo）

## 目的
列出正式軟體前端「必須讓使用者做到什麼」＋「哪些不能同時發生」,作為 UI/UX 設計輸入。**版面依使用者提供的線框／現代同類風格範例製作,本單不決定版面**（UI/UX 流程：需求 → 查閱現代同類風格 → 製作）。

## 使用者／情境
- 使用者：操作員／對客戶 Demo 的展示者。
- 情境：用我方軟體驅動 InSpec 量測,操作員不需看到/操作 InSpec;並展示三種能力——讀 InSpec 資料、改 InSpec 前端、無畫面驅動。

## 功能需求（FR）
| # | 需求 | 對應技術藍圖 |
|---|---|---|
| FR-1 | 連線狀態：顯示 InSpec 是否連線(PID)/已注入;可重新掃描、可無畫面啟動 | `藍圖_dll注入`／`藍圖_無畫面啟動` |
| FR-2 | 選程式：查詢 `.iwp`(目錄＋關鍵字→清單)並選取 | — |
| FR-3 | **無畫面量測(主流程)**：對選定 `.iwp` 以 iscmd 驅動執行＋AutoExport 讀值,InSpec 全程隱藏 | `藍圖_iscmd`／`藍圖_autoexport讀值`／`藍圖_無畫面啟動` |
| FR-4 | 結果呈現：把匯出檔資料以表格呈現(元素/值/公差/判定) | `藍圖_autoexport讀值` |
| FR-5 | 提示處理：程式含 `Prmt` 時,讓使用者提供提示值供程式化填入 | `藍圖_訊息注入` |
| FR-6 | **（必要,非展示選配）前端改造**：改的是 InSpec 自己顯示的畫面本身,不是我方軟體另開控制台代管——(a) 完成小圖示可換樣式(打勾/叉叉/自訂文字)與顏色,對應真實成敗語意;(b) 摘要面板「輸入值」那一行直接變成可點進去編輯的真正欄位,改完離開焦點會走「重新執行→回填→確認」寫回 InSpec 真實資料 | `藍圖_前端注入` |
| FR-7 | (展示)即時讀畫面：視窗可見時讀 InSpec 當下摘要 | `藍圖_gdi讀畫面` |
| FR-8 | 運作記錄：顯示每步真實結果(exit code/檔案 byte/例外)的 log,可開 log 檔 | `AppLog`(host middleware) |

## 非功能需求（NFR）
| # | 需求 |
|---|---|
| NFR-1 | 單頁、**無左側導覽欄**(使用者明確要求) |
| NFR-2 | 每個動作一眼看出「觸發什麼、影響什麼」 |
| NFR-3 | 主流程(FR-3/4)視覺為主;FR-6 是必要能力,常駐在主流程(②執行卡片內),不進可收合的進階區——FR-7(即時讀畫面)才是次要展示能力,收進可收合區 |
| NFR-4 | 狀態與結果即時回饋,不靠使用者猜 |
| NFR-5 | 依 UI/UX 設計學：先需求單 → 查閱現代同類(單頁/儀表板)風格 → 製作 |

## 互斥／干擾約束（C）— 來自技術干擾分析
| # | 約束（`條件 → 不可`） |
|---|---|
| C-1 | 兩條驅動並存 → 不可同時對同一 InSpec：主流程用 iscmd;工具列訊息注入僅 legacy/展示且需標示 |
| C-2 | 讀值路徑：主流程用 AutoExport 檔;GDI 讀畫面需視窗可見,與隱藏互斥 |
| C-3 | GDI 讀畫面 1s timer(裝 hook＋強制重繪) 與 iscmd 執行 → 不可同時啟用(互相干擾) |
| C-4 | 隱藏視窗 與 GDI 即時讀畫面 → 直接衝突(隱藏就讀不到) |
| C-5 | 前端改造(完成小圖示＋就地編輯欄位)、Demo 按鈕、LiveEdit 按鈕 → 共用一條監看執行緒,各自獨立旗標開關 |

## 明確排除（不進正式前端）
- 控制項偵查(`Dump*`,`藍圖_控制項偵查`)等診斷工具 → 只在 Sandbox。
- 一次性 `C:\` dump 檔路徑。
