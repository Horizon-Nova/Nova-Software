# Win32 訊息注入 藍圖

## 1. 定位
用 Win32 視窗訊息驅動 InSpec 的控制項（工具列按鈕、對話框輸入框/按鈕、選單命令),取代不可靠的合成滑鼠座標點擊。驅動部分已降為 legacy（正式驅動改走 `藍圖_iscmd`,§10）;提示填值仍在用。
依據規格：無正式規格,依控制項偵查（`藍圖_控制項偵查`）取得的真實 id + 實機記錄。

## 2. 範圍
- 涵蓋：工具列「執行」點擊、提示對話框填值+確定、檔案選單開檔。
- 排除：控制項 id 怎麼查到（→ `藍圖_控制項偵查`）、注入底座（→ `藍圖_dll注入`）。
- 姊妹：`藍圖_iscmd`（官方驅動）,比對 §10。

## 3. 資料模型
控制項 id（`藍圖_控制項偵查` 查得,非猜測）：
- 「執行」工具列 ← class `ToolbarWindow32` id `1165`,index 0=執行、1=自動連續、2=停止（**id 1166 是相鄰的 22 顆幾何工具面板,不是這個**）
- 提示對話框 ← 標題「輸入提示」,Edit 子控制項填值、第一個 Button＝確定
- 開檔選單 ← `WM_COMMAND` id `57601`（檔案→開啟舊檔）;開啟舊檔對話框（Explorer 風格）檔名 Edit id `1148`、開啟鈕 id `1`

## 4. 資料交換
無自訂契約——送的是標準 Win32 訊息（`WM_LBUTTONDOWN`/`UP`/`WM_SETTEXT`/`BM_CLICK`/`WM_COMMAND`）。

## 5. 端點與流程
執行（注入）：`FindToolbarById(1165)` → `TB_GETITEMRECT(index)` → `WM_LBUTTONDOWN`/`WM_LBUTTONUP` 於按鈕矩形中心
提示填值（注入）：`FindWindowW(NULL,"輸入提示")` → `EnumChildWindows` 找 Edit/Button → `WM_SETTEXT`（值）→ `BM_CLICK`（確定）
開檔（host 純跨行程,免注入）：`FindWindow("InSpecAppFrame")` → `PostMessage(WM_COMMAND,57601)` → 輪詢 `FindWindow("開啟舊檔")` → `GetDlgItem(1148)`/`GetDlgItem(1)` → `WM_SETTEXT`+`BM_CLICK`
程式碼：`InSpecHookDLL.cpp`（`ClickToolbar1165ButtonByIndex`／`AutoFillAndConfirmPrompt`／`TriggerOpenFileMenu`／`FindToolbarById`）、`InSpecController.cs`（`TriggerExecute`／`FillAndConfirm`／`OpenFileInInSpecAsync`）

## 6. 業務規則
- 合成滑鼠座標點擊不可靠：確定鈕多次無反應;工具列點擊時好時壞,根因是座標常落在相鄰 `ToolbarWindow32`(1166) → 改用 `TB_GETITEMRECT` 取正確矩形 + 直接對正確 HWND 送訊息。
- 訊息傳遞不要求視窗可見：主視窗 `SW_HIDE` 後,工具列點擊/對話框填值/確定仍送達生效（實測）——這是無畫面驅動可行的基礎。
- 開檔用 `PostMessage`（非同步）：`WM_COMMAND` 開檔會跑 modal 對話框迴圈,用 `SendMessage` 會卡到對話框關閉才返回。

## 7. 權限
工具列/提示填值需注入（`藍圖_dll注入`）;開檔的 `FindWindow`/`PostMessage`/`SendMessage` 是 host 直接跨行程,免注入。授權：原廠口頭同意。

## 8. 跨功能依賴
- 依賴：`藍圖_dll注入`（工具列/提示填值部分）、`藍圖_控制項偵查`（提供真實 id）。
- 被誰用：`FillAndConfirm` 仍被無畫面主流程用（程式含 `Prmt` 提示時,`iscmd /run` 會卡提示 → 靠這個填值續跑）。`TriggerExecute`／`OpenFileInInSpecAsync` 已被 `iscmd /run` 取代。

## 9. 已知限制／待決定／修正記錄
- 全鏈實機驗證（2026-07-29）：觸發執行→跳提示→填值→確定→摘要顯示真實值,零人工、零螢幕座標。
- ✗ 合成滑鼠座標點擊對此類舊 MFC 對話框無效的根因未查證（只確認現象,改走訊息注入繞過）。
- 提示填值目前是無畫面流程裡唯一還需注入的環節;若程式無 `Prmt`,整條無畫面量測可完全免注入。

## 10. 同系列比對
`藍圖_iscmd.md`——官方驅動。比對結論見該檔 §10：iscmd（官方、穩、免注入、免座標）取代訊息注入的「驅動/開檔」;訊息注入僅保留「提示填值」（iscmd 做不到）與作為 legacy 展示。
