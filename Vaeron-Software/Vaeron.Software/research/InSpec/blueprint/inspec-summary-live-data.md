# InSpec 摘要面板即時資料存取 藍圖

## 1. 定位

現場已取得原廠（Micro-Vu）授權對這款舊版 InSpec 做逆向工程的前提下，讓「摘要面板打勾覆蓋」從「只判斷完成與否」升級為「讀寫真實摘要資料」與「無需開啟 InSpec 視窗即可驅動執行」，讓我方軟體逐步取代 InSpec 前端角色（使用者原話：「InSpec 摘要面板完成打勾改造深究」）。

依據規格文件：無正式規格文件，依 2026-07-29 對話多輪澄清收斂記錄。與既有藍圖的關係：**延用** `inspec-hookdll-overlay.md` 的 HookDLL 注入基礎設施、控制項錨定（GXWND/1268、值/1266、旗標/1264、`ToolbarWindow32`/1166）、監看執行緒＋旗標模式、「完成訊號一律沿用 InSpec 自身狀態」判準；**不推翻**該檔已實作並實測通過的打勾覆蓋層／Demo 按鈕；本檔範圍是在此基礎上新增「真實資料讀取」「編輯回寫」「無視窗驅動執行」三項能力。**修正原先「`inspec-hookdll-overlay.md` 本身不修改」的宣告**：該檔 §10「判準」本身是持續累積的技術判準表（例如既有 `SetTimer` 那條），本輪撞出的兩條新判準（合成滑鼠點擊對 InSpec 對話框無效、UI Automation 對 InSpec 主視窗無支援）屬於該表既定用途，已加入該檔 §10，不是改寫其功能描述或推翻其結論。

## 2. 範圍

涵蓋：
- 讀取摘要面板真實文字數值（不只 1264 可見性布林），我方軟體自行顯示，取代原摘要畫面呈現
- InSpec 工具列（`ToolbarWindow32`/1166 群組，本輪已實機確認位置：「元素」清單右側、執行圖示所在那排）新增按鈕，開輸入框顯示摘要項目並可編輯；改值後 InSpec 本身與我方顯示需同步（讀寫同一份資料源，非各自維護副本）
- 我方軟體驅動 InSpec 在背景（視窗隱藏）執行量測與設定，使用者全程不需看到/操作 InSpec 視窗（B 模式）
- 查詢能力：解析掃碼槍輸入的 BarCode 字串取得料號，依料號比對 `.iwp` 檔案清單，方便使用者找到對應的 InSpec 程式檔（規則見 §4／§5）

明確排除：
- 不重新實作 InSpec 的量測演算法／引擎本身——量測邏輯完全沿用 InSpec 既有 `.iwp` 程式檔（本輪測試檔：`CDA343-AD SETUP`，路徑 `供測試用 (1)\STV\C\CDA343-A\`）
- 不使用 UI Automation——本輪實機驗證 InSpec 主視窗無 UIA 支援（§9）
- 不沿用先前討論過的 Java/JavaFX 或 .NET WPF 查詢畫面移植方案（§10，已排除）

## 4. 資料交換

本功能無對外 HTTP/API 契約；「資料交換」的等價物是 HookDLL 匯出函式與 InSpec 記憶體/視窗訊息之間的契約，格式比照既有藍圖第 6 節延伸。以下皆為**提案，未實作**：

### 摘要真實值讀取——方向：從 InSpec 讀出

| 欄位 | 型別 | 必 | 說明 |
|---|---|---|---|
| PromptName | string | 是 | ← 摘要面板「提示」標籤文字 |
| InputValue | string | 是 | ← 摘要面板「輸入」欄實際值。**讀取方式已完整實測驗證成功**：`GetWindowText` 枚舉（`DumpSummaryControls`）確認 GXWND(1268) 本身文字為空，此路不通；改攔截 GXWND `WM_PAINT`（實測確認走標準 `BeginPaint`/`EndPaint`）期間呼叫的 `TextOutW`/`ExtTextOutW`（`CaptureGxwndPaint`，擴充既有 `InstallAllHooks` IAT hook 基礎設施），**成功攔截到含實際值的完整繪製內容**：固定版面 `x=50`，`"提示:"`(y=1) / `"{提示名稱}"`(y=18) / `"輸入:"`(y=38) / `"{實際輸入值}"`(y=55)，四行版面與數值皆經 2026-07-29 實機測試（自動化全流程，見 §5/§6）驗證，非推測 |

外層結構：`?` 未定（單筆／整批摘要清單一次回傳，未決定）。成功／失敗範例：`?` 未實測；失敗時比照既有藍圖判準——錨點找不到絕不計算位址並呼叫，下一輪（300ms）重試，不報錯。

### 摘要值編輯回寫——方向：送進 InSpec

| 欄位 | 型別 | 必 | 說明 |
|---|---|---|---|
| PromptName | string | 是 | 對應要修改的提示項目 |
| NewValue | string | 是 | 使用者在我方軟體輸入框填入的新值 |

外層結構：`?` 未定；回寫手法 `?` 未定，候選：重新觸發 InSpec 原生「提示」對話框，用 `WM_LBUTTONDOWN`/`WM_LBUTTONUP` 訊息注入送出「確定」——理由見 §6（本輪實測合成滑鼠座標點擊該按鈕無效）。成功／失敗範例：`?` 未實測。

### BarCode 解析——方向：使用者輸入 → 我方軟體

| 欄位 | 型別 | 必 | 說明 |
|---|---|---|---|
| RawBarCode | string | 是 | 掃碼槍/手動輸入的原始字串，格式見 §3 BarCode 字串列 |

外層結構：純字串，無 envelope。成功範例：`|CDA343-AD410.M1K.29|401657140|STV-557|4W0044621|09/17/2025|09/17/2030|`（使用者本輪提供的真實範例）。失敗範例：`?` 未定義（格式不符時如何處理未查證）。

### 料號正規化——方向：純運算

| 欄位 | 型別 | 必 | 說明 |
|---|---|---|---|
| PartNumberRaw | string | 是 | ← BarCode 第 1 欄，例：`CDA343-AD410.M1K.29` |
| PartNumberNormalized | string | 是 | → 例：`CDA343-AD`，去除數字尾碼、只留字母代號；本輪僅驗證這一組範例，`?` 精確演算法（例如料號本身含多段數字時如何切分）未查證，不可自行推測套用到其他料號格式 |

### `.iwp` 檔案查詢——方向：我方軟體查目錄

| 欄位 | 型別 | 必 | 說明 |
|---|---|---|---|

| MatchedFiles | string[] | 是 | → 檔名含 `PartNumberNormalized` 子字串的 `.iwp` 檔案清單 |

## 5. 端點與流程

延用既有藍圖監看執行緒＋錨點重找架構，新增流程（皆為提案，未實作）：

- **讀取真實值**（**已實機驗證**，見 §4）：找到摘要面板 GXWND（`FindSummaryGrid`，沿用既有 `FindMainProc` 錨點邏輯）→ 對其強制觸發重繪（`InvalidateRect`+`UpdateWindow`）→ hook 攔截這次重繪期間的 `TextOutW`/`ExtTextOutW` 呼叫 → 取得完整四行內容（提示標籤/提示名稱/輸入標籤/實際值）。正式功能應改成監看執行緒每輪主動觸發（既有 300ms 週期），而非本輪這種一次性診斷呼叫。
- **無視窗驅動執行（B 模式）——2026-07-29 已實機驗證，寫入與讀取結論不同，分開陳述**：`ShowWindow(SW_HIDE)` 隱藏 `InSpecAppFrame` 後，`TB_GETITEMRECT`+`WM_LBUTTONDOWN`/`UP`（工具列執行鈕）→`WM_SETTEXT`+`BM_CLICK`（提示對話框填值確認）整條寫入鏈**仍正常送達並生效**——重新顯示視窗後摘要面板正確顯示打勾與真實值，證實 Win32 訊息傳遞不要求目標視窗可見。但**讀取真實值（§4 的 `CaptureGxwndPaint` GDI 攔截法）在隱藏狀態下失效**：`InvalidateRect`+`UpdateWindow` 對隱藏視窗不會觸發 `WM_PAINT`（Windows 對不可見視窗抑制繪製），實測 log 只看到其他視窗的 `GetDC` 呼叫，目標 GXWND 完全沒有進入攔截到的繪製流程。**結論：B 模式「驅動」（寫入）已證實可行，但「即時讀值」需要另尋不依賴實際繪製的手段（例如視窗短暫顯示又隱藏、或改抓 InSpec 內部資料結構而非畫面繪製），現有 GDI 攔截技術不能直接搬進純隱藏情境。**
- **編輯回寫**：使用者點我方新增按鈕 → 開我方自己的輸入框（非 InSpec 原生對話框）→ 使用者填新值 → HookDLL 重新觸發 InSpec 原生「提示」流程（沿用上面已驗證的 `WM_SETTEXT`+`BM_CLICK` 手法，這部分機制已具備，未驗證的是「已完成一次後再次修改」這個情境本身會不會有差異，見 §9）→ InSpec 自身摘要更新 → 讀取真實值流程下一輪讀到新值 → 我方顯示自動同步（讀寫同一份資料源，非我方自行維護副本後再手動同步）。
- **查詢**：使用者輸入/掃描 BarCode 字串 → 依 `|` 切分取第 1 欄 → 正規化去除數字尾碼取得料號 → 對 `SearchDirectory` 掃描 `.iwp` 檔名含該料號子字串 → 回傳清單供使用者選取 → `?` 選取後動作未定案（直接讓 InSpec 開啟該檔／只是列出來給人看，見 §9）。

## 5-B. 無畫面正解：export 檔 + iscmd（2026-07-29 架構轉向，取代上方 GDI 讀值＋工具列驅動）

**目標句（無損重組對撞後的結論）：** 上方 §5「讀取真實值（GDI 攔截）」與「工具列訊息注入驅動」都是**把資料與控制繞過螢幕去做、再把視窗藏起來**——這正是「打開再隱藏、硬讀畫面」的錯誤方向（使用者指出）。原廠本來就有**不經螢幕**的路徑，先前沒挖到才誤判「純隱藏讀不到值＝無畫面做不到」。正確路徑：

| 面向 | 錯誤舊路（上方 §5） | 正解（本節） |
|---|---|---|
| 控制/驅動 | 注入 DLL→`FindToolbarById(1165)`→`WM_LBUTTONDOWN`/`UP`；開檔用 File→Open 選單注入 | **`iscmd.exe /run "檔案.iwp" [/nowait]`**（原廠官方指令，手冊附錄 B）、`iscmd /halt` 停止 |
| 資料/讀值 | 注入 DLL→`CaptureGxwndPaint` 攔截 `TextOutW` 讀畫面（隱藏時失效） | **InSpec 自身 AutoExport 寫檔**：`.iwp` 內 `(AutoExpFile "路徑") (AutoExpFileInf ((Enab 1) (Conf 0) ...))`，每次執行把量測資料寫進該 `.txt`，我方讀檔 |
| 隱形 | 讀畫面所以視窗必須可見/可繪製，隱藏就讀不到 | 因為資料改走檔案、控制改走 iscmd，**沒有東西依賴視窗繪製**，`SW_HIDE`（或離螢幕）即可,「隱藏讀不到值」的矛盾消失 |

**已實機驗證（外部執行，非推導，2026-07-29）：**
- `iscmd /run "檔案" /nowait` exit code 0，InSpec 標題列由「未命名」變成該檔名 → 確認 iscmd 開檔＋啟動程式。
- 把測試 `.iwp` 複製一份、`(AutoExpFileInf ((Enab 0)` 改 `((Enab 1)`＋填 `AutoExpFile` 路徑後 `iscmd /run` → **InSpec 在該路徑產生匯出檔**（`inspec_export_proof.txt`），全程我方沒碰畫面。檔案為 0 bytes：因為此 SETUP 測試檔無實際量測元素、無真機台、提示值未進去；**機制證實可行，真實內容要有量測元素的程式＋真機台才有值**（未驗證，見 §9）。

**iscmd 完整能力（手冊附錄 B，窮舉）：** 只有 `iscmd /run 檔案`（同步，等到量測完）、`iscmd /run 檔案 /nowait`（非同步）、`iscmd /halt`（停止）三個；回傳非零＝InSpec 沒在執行或參數不認得。**不回傳資料**（資料走 AutoExport 檔）、**不做前端注入**。iscmd 是本機命名事件（`OpenEventA`）→ 要求 InSpec.exe 這個 GUI 行程活著（引擎＝行程，省不掉；但視窗可隱形）。

**DLL 注入在新架構的殘留用途（不是全砍）：** (1) 若程式含 `Prmt` 提示，`iscmd /run` 會卡在提示，需要 `AutoFillAndConfirmPrompt` 程式化餵值（提示對話框即使主視窗隱藏也收得到訊息，§6 #5 已驗證）；(2) 前端注入按鈕 Demo（`EnableLiveEditButton`）；(3) 原始打勾覆蓋層。核心「量測+讀值」迴圈不再需要注入。

**尚未驗證（誠實列出，見 §9）：** 匯出檔真實量測內容需真機台；提示要完全無人值守需「無提示程式」或「提示值程式化」；AutoExport 是編輯 `.iwp` 副本啟用（不動客戶原檔）還是走 InSpec.ini／Playback Options 全域設定，未定案。

## 6. 業務規則

| # | 條件 | 結果 |
|---|---|---|
| 1 | 我方軟體顯示的摘要值改變 | 一律因為讀到 InSpec 內部資料源的變動，不是我方自行維護獨立副本後再同步——跟既有藍圖「完成訊號一律沿用 InSpec 自身狀態」同一精神，本輪延伸到「內容」而非只「完成與否」 |
| 2 | 對 InSpec 對話框按鈕／工具列按鈕送合成滑鼠座標點擊（螢幕座標模擬） | 不可靠——`確定` 鈕多次無反應；「執行」工具列按鈕時好時壞，事後查出根因是坐標常落在相鄰的 `ToolbarWindow32`(id 1166) 上，不是同一顆（見 #4） |
| 3 | 對 InSpec 對話框／工具列按鈕改走 Win32 訊息注入（工具列用 `TB_GETITEMRECT`+`WM_LBUTTONDOWN`/`UP`；輸入框用 `WM_SETTEXT`；按鈕用 `BM_CLICK`） | **生效，2026-07-29 全流程實機驗證**：觸發執行→跳出提示框→自動填值→自動按確定→摘要面板正確顯示真實值，全程零人工介入、零螢幕座標依賴 |
