# 控制項偵查 藍圖

## 1. 定位
把 InSpec 的視窗/選單/工具列結構 dump 成檔案,查出真實控制項 id 與命令 id,讓其他技術以「查到的事實」而非猜測去操作。屬研究/測試工具,不進正式交付（歸 Sandbox,§8）。
依據規格：無正式規格,逆向偵查工具。

## 2. 範圍
- 涵蓋：dump 主選單命令 id、任意視窗子控制項樹（class/id/text）、開啟舊檔對話框、全部工具列 + 特定工具列(1165)。
- 排除：查到 id 後怎麼用（→ `藍圖_訊息注入`）、注入底座（→ `藍圖_dll注入`）。

## 3. 資料模型
輸出檔（固定路徑,一次性 dump）：
- `C:\InSpecHookDLL_menu.txt` ← 主選單頂層+子項 id
- `C:\InSpecHookDLL_dump.txt` ← 摘要對話框子控制項樹
- `C:\InSpecHookDLL_opendlg.txt` ← 開啟舊檔對話框子控制項樹
- `C:\InSpecHookDLL_alltoolbars.txt`／`_toolbar1165.txt` ← 工具列列舉

## 4. 資料交換
### dump 檔——收到
| 檔 | 內容格式 |
|---|---|
| menu | `[top i] "文字"` / `  [sub j] id={id} "文字"` |
| controls | `hwnd=0x… class={cls} id={id} text="{t}"`（縮排＝層級） |
| toolbar | `[i] idCommand={id} rect=(…) text="…"` ← `TB_GETBUTTON`/`TB_GETITEMRECT` |

已查得並被其他藍圖使用的關鍵事實：檔案→開啟舊檔 cmd id `57601`;開檔對話框檔名 Edit id `1148`、開啟鈕 id `1`;執行工具列 id `1165`（≠1166）。

## 5. 端點與流程
DLL 匯出 → `EnumChildWindows` 遞迴 / `GetMenu`+`GetSubMenu`+`GetMenuStringW`+`GetMenuItemID` / `TB_BUTTONCOUNT`+`TB_GETBUTTON`+`TB_GETITEMRECT` → `fwprintf` 寫固定路徑檔
匯出：`DumpMainMenu`／`DumpSummaryControls`／`DumpOpenDialogControls`／`DumpAllToolbars`／`DumpToolbar1165`
程式碼：`InSpecHookDLL.cpp`（上述 + `DumpChildProc`／`DumpOpenDialogChildProc`）

## 6. 業務規則
- 一次性診斷：呼叫一次 dump 一次到固定 `C:\` 路徑,非即時/非產品介面。
- 觸發選單命令用 `SendMessageW(main, WM_COMMAND, id)`（id 來自 `DumpMainMenu`,非猜）。

## 7. 權限
需注入（`藍圖_dll注入`）。授權：原廠口頭同意。

## 8. 跨功能依賴
