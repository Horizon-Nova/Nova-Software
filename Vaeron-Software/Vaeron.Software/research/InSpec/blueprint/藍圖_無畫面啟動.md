# 無畫面啟動 藍圖

## 1. 定位
讓 InSpec 從行程建立那一刻就不顯示視窗（非先顯示再隱藏),並在 iscmd 開檔使其自我顯示後補隱藏,使操作員全程看不到 InSpec。
依據規格：無正式規格,依 .NET `ProcessStartInfo`／Win32 `ShowWindow` 行為 + 實機記錄。

## 2. 範圍
- 涵蓋：以隱藏方式啟動 InSpec、隱藏/顯示主視窗、iscmd 執行後 re-hide。
- 排除：啟動後怎麼驅動/讀值（→ `藍圖_iscmd`／`藍圖_autoexport讀值`）。

## 3. 資料模型
主視窗 ← class `InSpecAppFrame`;可見性 ← Win32 `IsWindowVisible`（`null`＝視窗不存在）。

## 4. 資料交換
無——本功能不涉及資料交換,只控制行程與視窗顯示狀態。

## 5. 端點與流程
啟動：`LaunchInSpecHidden(exe)` → `Process.Start(ProcessStartInfo{UseShellExecute=true, WindowStyle=Hidden})` → `Sleep(1500)` 等初始化 → `AttachToProcess`（注入,見 `藍圖_dll注入`）
隱藏/顯示：`HideMainWindow`/`ShowMainWindow` → DLL 匯出 `ShowWindow(InSpecAppFrame, SW_HIDE|SW_SHOW)`
探測：`IsMainWindowVisible()` → `FindWindow("InSpecAppFrame")` + `IsWindowVisible`
程式碼：`InSpecController.cs`（`LaunchInSpecHidden`／`HideMainWindow`／`ShowMainWindow`／`IsMainWindowVisible`）、`InSpecHookDLL.cpp`（`HideMainWindow`／`ShowMainWindow` 匯出）

## 6. 業務規則
- 必須 `UseShellExecute=true` 才能讓 `WindowStyle=Hidden` 生效：`UseShellExecute=false`＋`CreateNoWindow=true` 時 .NET 會忽略 `WindowStyle`,InSpec 仍以預設顯示狀態啟動（本 session 實測失敗後改正）。
- `iscmd /run` 開檔會讓已隱藏的 InSpec 主視窗 self-activate 重新顯示 → 流程結束需再呼叫 `HideMainWindow` 補隱藏。
- 引擎＝行程：InSpec 是 MFC GUI app,量測引擎與視窗同一行程,視窗物件一定存在,只能「不可見」不能「不存在」。單機下沒有「完全無視窗」;使用者過往的「無畫面」是把 InSpec 放另一台機器（操作員那台無 InSpec）——那是機器分離,不在本檔單機範圍。

## 7. 權限
啟動 InSpec 需可執行該 exe;隱藏/顯示需注入（`藍圖_dll注入`）或視窗控制權。授權：原廠口頭同意。

## 8. 跨功能依賴
- 對外暴露：`LaunchInSpecHidden`／`Hide`／`Show`／`IsMainWindowVisible`（`InSpecController`）。
- 依賴：`藍圖_dll注入`（Hide/Show 匯出需注入）;被 `藍圖_iscmd` 依賴（/run 重顯示後需本檔 re-hide）。

## 9. 已知限制／待決定／修正記錄
- 隱藏啟動：已實機驗證（2026-07-30，`AppLog` 記錄 `LaunchInSpecHidden` → `AttachToProcess` 成功 → `IsWindowVisible=True`(注入完成當下)→ `HideMainWindow` → `IsWindowVisible=False`）。
- ~~UseShellExecute=false 隱藏失敗~~——已修正為 `UseShellExecute=true`。
- **`FindWindow`/`FindWindowW` 外部探測隱藏視窗不可靠（2026-07-30 新查獲，根因未定）**：獨立 PowerShell 行程呼叫 `FindWindow("InSpecAppFrame", NULL)` 對已隱藏視窗一律回傳找不到（`NOT FOUND`），已排除進入點解析（顯式 `EntryPoint="FindWindowW"` 同樣失敗）、行程位元數（32-bit PowerShell 同樣失敗）兩個假設；改用 `EnumWindows`＋`GetWindowThreadProcessId` 過濾同一支外部探測腳本，**能正確找到**該隱藏視窗且 `IsWindowVisible` 正確回報 `False`。**產品本身不受影響**：`InSpecController.IsMainWindowVisible()` 是從 app 行程內部呼叫同一個 `FindWindow` API，`AppLog` 證實運作正常（見上一條）；只有「外部另開行程呼叫 FindWindow」這條路徑異常。外部驗證改用 `Sandbox/scripts/probe_all_windows.ps1`，`probe_visible.ps1` 標記失效。
